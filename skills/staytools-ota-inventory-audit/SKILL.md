# OTA 재고 조사 에이전트

## 이 스킬이 푸는 문제

야놀자·여기어때 **모텔 카테고리처럼 재고가 CMS로 연동되지 않은 채널**은 파트너센터에서 직접 설정한 값이 곧 실제 판매 설정이고, 아무도 손대지 않으면 영원히 그대로다. 그래서 이런 일이 조용히 생긴다.

연동 여부는 **CMS 화면의 표시만 보고 판단하지 말고 채널의 재고 연동 상태를 직접 확인한다.** 한 숙소 관측: CMS에 그 채널이 `연동 완료`로 떠 있었지만 야놀자 `roomInventoryLinkStatus`는 전 칸 `UNLINKED`였다 (`references/sites.md`). 요금 전송 여부는 **확인 필요**다 — 연동됐다고 가정하지 마라.

- 앞으로 한 달치 재고를 아무도 안 넣어서 **한 달 통째로 매진(재고 0)** — 실제로 두 달 연속 그런 사례가 있었다
- PMS엔 방이 남아 있는데 OTA에서만 수동 마감이 안 풀려 **며칠씩 판매 손실**
- PMS 잔여가 0인데 OTA는 열려 있어 **오버부킹 위험**

## 시작 — 숙소 프로필을 먼저 확정한다

**이 배포본에는 특정 숙소의 값이 없다.** 객실 매핑·상품 목록·운영 예외·오버부킹 허용치·요금 기준은 전부 프로필에서 온다.

1. 작업 폴더나 이 스킬 폴더에 `hotel-profile.md` 가 있으면 읽는다.
2. 없으면 `hotel-profile.example.md` 양식의 항목을 사용자에게 받거나 화면에서 읽어 채운다.
3. **프로필에 없는 예외를 지어내지 않는다.** 예외 목록에 없는 불일치는 일단 "문제 후보"로 올리고, 일부러 그렇게 둔 것인지 사용자에게 확인한다.

브라우저 도구가 없는 환경이면 화면 수집 대신 **사용자가 준 자료(PMS 잔여표, 채널별 재고·상태 표, CSV·엑셀)** 로
같은 판정을 한다. 이때 조치는 "조치안"까지만 쓰고, 직접 고쳤다고 쓰지 않는다.

표 자료로 판정할 때:
- **행이 없는 칸은 `미설정`인지 내보내기 누락인지 알 수 없다.** 판정하지 말고 "자료에 없음 — 확인 필요"로 남긴다.
- 프로필에 없는 상품은 판매 손실로 세지 말고 **확인 필요**로 분리한다.
- 판정은 **칸(날짜 × 상품 × 채널) 단위**로 적는다. 객실 타입이 오버부킹 위험 상태여도 그 채널 칸이 이미 닫혀 있으면
  대조표에 "위험 — 이미 마감, 조치 불필요"로 표시만 하고 **조치안 목록에는 넣지 않는다** (`references/rules.md` 5번과 같은 뜻이다).
- 조치안에는 "상태만 열면 됨"과 "재고를 올려야 함"을 구분해 적는다.
- 자료가 조사 범위 전체를 덮지 못하면(예: 다음 달 자료 없음) 보지 못한 구간을 보고서에 적는다.
- 아티팩트를 발행할 수 없는 환경이면 `references/report.md` 의 구성 요소를 파일 하나에 담아 준다.

## ★ 제1원칙

**재고를 몇 실로 넣느냐는 중요하지 않다. 중요한 건 오픈이냐 마감이냐다.**
PMS에 방이 1실이라도 남아 있으면 OTA에서 **팔리는 상태**여야 한다.

그래서 `마감` / `매진(잔여 0)` / `미설정` 은 전부 같은 문제다 — 표시만 다르지 결과는 "못 판다"로 똑같다.
**판매상태가 '판매'라는 이유로 정상이라고 넘기지 마라.** 야놀자는 `saleOpen:true`인데 `reservableQuantity:0`,
여기어때는 `status:1`인데 `total_stock:0`이면 매진이다. PMS에 방이 있으면 이건 판매 손실이고,
**재고를 올려서 여는 게 정답이다 — 숫자를 얼마로 할지는 물어볼 일이 아니다.** 같은 상품의 다른 날짜 값을 쓰면 된다.

## 작업 순서

1. **PMS에서 기준 재고를 읽는다** — `references/sites.md`의 PMS 절차
2. **OTA 숙박/대실을 전수 수집한다** — 같은 문서의 채널별 절차. 가상 스크롤 우회법을 반드시 지킬 것
3. **판정한다** — `references/rules.md`(마감/오픈)와 `references/rateplan.md`(요금제). 정상으로 걸러야 할 패턴이 여럿이라 이 두 문서와 프로필의 운영 예외를 건너뛰면 오탐이 쏟아진다
4. **분명한 건은 고치고, 애매한 건은 물어본다** — `references/fix.md` (프로필의 「조치 권한」이 "조회·조치안까지만"이면 고치지 않는다)
5. **보고한다** — `references/report.md`
6. **기록한다** — 세션에서 새로 알아낸 것과 잘못 판단한 것을 `references/lessons.md` 의 「이 숙소의 세션 로그」 맨 위에 추가한다. 빠뜨리지 마라
   (스킬 폴더에 쓸 수 없는 환경이면 사용자의 작업 폴더에 `lessons.md` 로 남기고 위치를 알려준다)

## 판정 기준 (요약)

| 상황 | 판정 |
|---|---|
| PMS 잔여 > 0, OTA 마감 | **판매 손실** → 연다 |
| PMS 잔여 0, OTA 판매 | **오버부킹 위험** → 닫는다 (프로필의 오버부킹 허용치를 먼저 적용) |
| OTA 매진(잔여 0)인데 PMS엔 방 있음 | **마감과 동일한 판매 손실** → 재고를 올려 연다 (오픈 토글로는 안 고쳐진다) |
| OTA 미설정 | 상품이 등록조차 안 됨 → 운영 상품이면 새로 등록 |
| 요금제가 그 날짜의 휴무 조합과 안 맞음 | **요금제 오류** → 같은 tier의 정상 날짜에서 복사 |

정상이라 손대면 안 되는 것들은 `references/rules.md` 와 프로필의 「운영 예외」에 있다. **먼저 읽어라.**
이 작업에서 실제로 틀렸던 것들은 `references/lessons.md`에 있다. **작업 시작 전에 같이 읽어라 — 같은 실수를 반복하지 않는 게 목적이다.**

## 자동으로 고쳐도 되는 것 / 물어봐야 하는 것

프로필의 「조치 권한」이 "분명한 건은 자동 수정"일 때의 기준이다. 기록이 없으면 **조치안만 내고 수정 전에 승인을 받는다.**

자동으로 고친다:
- PMS에 방이 남아 있는데 OTA만 닫힌 객실 상품을 여는 것
- **잔여 0(매진)인데 PMS엔 방이 남은 칸의 재고를 올려 파는 상태로 만드는 것** — 숙박·대실 모두
- 프로필의 운영 예외에 "이 날은 닫혀 있어야 한다"고 적힌 상품이 열려 있는 것을 닫는 것 (예: 조식 미운영일 전날의 조식 포함 상품)
- 요금제가 명백히 어긋난 날짜를, 같은 달 같은 tier 날짜의 값을 그대로 복사해 맞추는 것

### 🚫 재고 파악은 오늘을 제외한 날짜다

**오늘 날짜는 조사 대상 자체가 아니다.** 조회도, 판정도, **보고도**, 조치도 하지 않는다. 물어보지도 마라.
데이터를 수집할 때부터 `date > 오늘`로 필터를 걸어라. 범위는 항상 **내일부터** 시작한다.

이 규칙은 운영자가 여러 번 강조한 기본값이다. 조치를 안 했어도 오늘 칸을 **보고**하는 것 자체가 범위 위반이다.
오늘 칸은 화면에 올리지도 마라. (사용자가 이번 조사에 한해 "오늘도 포함"이라고 명시했을 때만 예외다.)

반드시 물어본다:
- 요금을 새로 정하는 일 (기존 요금 복제가 아니라면)
- 평소 계속 닫혀 있던 상품을 여는 것 — 일부러 닫아둔 것일 수 있다
- 프로필에 없는 새 상품이 보일 때 — 특정 날짜에만 붙이는 판촉 상품일 수 있다
- 조사 범위를 벗어난 날짜
- **한 달이 통째로 못 파는 상태인 구간을 여는 것** — 위 자동 수정 대상이 아니다. 보고만 한다 (`references/fix.md`의 「한 달 오픈」)

## 조사 범위

기본은 **내일부터 30일** (오늘은 제외). 다만 한 달 통째로 죽는 사고가 실제로 있었으므로, **다음 달 말일까지 전체와 그다음 달의 첫 며칠도 같이 훑어서** 재고가 아예 안 들어간 구간이 있는지 확인한다. 재고 미투입 구간을 찾으면 날짜 범위를 그 달 전체로 넓혀 보고한다.
사용자가 범위를 지정했으면 그 범위를 따른다.

**조사 시작 때 오늘 날짜를 직접 확인한다** — 작업 환경의 시계가 아니라 **브라우저 시계**(`new Date().toString()`)를 프로필의 시간대 기준으로 읽는다. 사용자 말이나 앞선 턴의 날짜를 믿지 마라. 긴 세션은 날짜가 넘어간다.
PMS는 나이트 오딧 **영업일** 기준이라 새벽에는 달력과 하루 다를 수 있다. 두 값이 갈리면 **하루 더 보수적으로 제외**한다 — 오늘을 건드리는 것보다 하루 놓치는 게 낫다.

## 주의

- 화면에서 읽은 값만 믿는다. 고친 뒤에는 **반드시 다시 읽어서 확인**하고, 확인 못 한 건 "했다"고 보고하지 않는다.
- 임박 날짜의 PMS 잔여는 계속 움직인다. 수량은 참고만 하고 판정은 열림/닫힘으로 한다.
- 야놀자 캘린더 하단의 **`일괄 마감`(빨간 버튼)은 절대 누르지 않는다.** 선택된 날짜 전체를 닫아버린다. `저장` 바로 옆에 있으니 좌표로 클릭할 때 특히 조심.
- 로그인은 사용자가 한다. 로그인이 풀려 있으면 해당 사이트만 알려 주고 기다린다. 대신 로그인하지 않는다.
- 투숙객 이름·연락처·예약번호는 수집하지도, 보고서에 넣지도 않는다. 재고 대조에는 필요 없다.
- 판매 손실 금액은 요금과 수요 근거가 있을 때만 추정하고, 추정이라고 표시한다.
