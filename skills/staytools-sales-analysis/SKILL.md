# 월간 채널별 매출분석

**이 배포본에는 특정 숙소의 값이 없다.** 숙소명·객실 타입·거래처·수수료·쿠폰 부담·부가세 기준은 전부 「숙소 프로필」과 매핑 JSON에서 온다.

운영자가 원하는 것은 **보기 쉬운 그림 + 짧은 결론**이다. 숫자 나열로 끝내지 않는다.

## ★ 시작하기 전에 반드시 할 것 세 가지

### 0) 숙소 프로필을 확정하라

작업 폴더나 이 스킬 폴더에 `hotel-profile.md` 가 있으면 읽는다. 없으면 `hotel-profile.example.md` 양식의 항목을 사용자에게 받아 채운다.
**프로필에 없는 값은 지어내지 않는다.** 금액 기준을 모르는 채널은 `확인필요` 로 둔다.

### 1) 매핑 JSON을 정하라

| PMS | 시작 파일 | 상태 |
|---|---|---|
| YFlux | `scripts/mapping-yflux.json` | 기본 프리셋. 한 숙소의 실제 내보내기로 원본 빌더와 대조함 |
| 그 밖의 PMS | `scripts/mapping-template.json` | **미검증.** `verified: false` 로 두면 결과에 「미검증 매핑」이 표시된다 |

프리셋은 복사해서 쓰고, 프로필의 값을 옮겨 넣는다. 다른 PMS는 내보내기 첫 몇 줄의 **열 이름만** 보고 매핑한다. 값이 든 행은 대화에 옮기지 않는다.

### 2) 열의 뜻을 확인하라

열 이름이 같아도 뜻은 PMS마다 다르다. 처음 쓰는 PMS는 아래 세 가지를 예약 몇 건으로 확인하고 프로필에 적는다.

| 질문 | 틀리면 |
|---|---|
| 금액 열은 **받은 돈**인가 **예약 금액**인가 | 미수·환불 예약의 매출이 틀린다 |
| 체크인 열은 **예정일**인가 **실제 입실 시각**인가 | 당일 예약 비중·요일·박수·달 경계가 틀린다 |
| 객실 타입 열은 **판매한 객실**인가 **배정한 방**인가 | 업그레이드 배정이 많으면 윗 객실이 잘 팔린 것처럼 나온다 |

## 결과물

대시보드가 첫 탭인 엑셀 한 개.

| 탭 | 내용 |
|---|---|
| 대시보드 | KPI 6개(전월 대비 ▲▼) · 보고서 비교 상자 · 이번 달 핵심 · 차트 7개 · 읽는 법 |
| 채널별 | 채널 표(매출 막대·전월 대비·1박 평균·금액 기준·당일 비중·취소율) + 기타 채널 + 대분류 |
| 리드타임 / 요일 / 투숙일수 | 채널 × 범주 비중 히트맵 + 건수 표 |
| 객실 | 판매 기준 객실 구성(객실 타입 그대로) + 판매→배정 표 + 상품 묶음 + 객실별 1박 평균 |
| 국적 / 기업기관 | 국적 건수·확인 비율 / 업체별 실적 |
| 청구대조 | `--billing` 을 넣었을 때 생김. 보고서와 분석의 차이를 이유별·예약별로 풀이 |
| 채널구분표 | 거래처 → 채널·대분류·금액 기준 (고치면 전체가 따라 바뀜, 노란 줄 = 자동 분류) |
| 전월 / 차트데이터 / 원본 | 전월 집계 / 차트가 읽는 숫자 / 예약 행 + 파생 수식 |

## PMS 화면 함정 (다른 PMS도 같은지 먼저 본다)

1. **기간** — 검색과 내보내기가 입실한 예약을 *실제 입실 날짜*로 거르는 PMS가 있다. 말일 밤 손님이 다음 날 새벽에 입실하면 옆 달로 넘어간다.
   → 내보내기를 **앞뒤 하루 넓게**(전달 말일 ~ 다음 달 1일) 받고 `--month YYYY-MM` 으로 거른다.
2. **날짜** — 체크인·체크아웃이 실제 입·퇴실 시각이면 자정 넘어 입실한 손님이 하루 밀린다. → 예정일 보정 `--sched`. 없으면 당일 예약 비중이 낮게, 요일·박수가 틀리게 나온다.
3. **금액** — 금액 열이 받은 돈이면 **예약 금액 = 받은 금액 + 잔액** 이다. YFlux 프리셋이 그렇게 계산한다. 금액 열 하나로 끝나는 PMS는 `예약 금액` 항목에 매핑한다.
4. **객실** — 객실 타입 열이 배정 방이면 `--prod` 로 판매 기준을 준다. 없으면 대시보드·[객실] 탭에 경고가 자동으로 들어간다.

YFlux에서 확인된 동작: 위 네 가지 모두 해당한다. 내보내기의 `총 청구 금액`은 받은 돈이고, `객실 타입`은 배정 방이다.

### 기간 기준 두 가지

- 기본 = **예정 체크인일 기준** (`--month`): 손님이 예약한 날짜로 달을 나눈다.
- **PMS 화면 기준** (`--month` + `--basis pms`): PMS 검색 결과와 건수·금액이 같다. 리드타임·요일·박수는 어느 쪽이든 예정일 기준이다.
- 사용자가 기간을 애매하게 말하면 만들기 전에 어느 기준인지 먼저 묻는다.

### 매출 기준 — 분석과 보고서는 원래 다르다

| | 묶는 방식 | 달을 넘긴 장기투숙 |
|---|---|---|
| 예약 기준 | 체크인한 달에 예약 전액 | 체크인 달에 몰린다 |
| 청구(매출) 보고서 | 손님이 묵은 밤마다 나눠 그 달에 넣음 | 달마다 나뉜다 |

운영자가 말하는 「월 매출」이 PMS 보고서 숫자라면 `--billing-acc` 를 넣어 대시보드 매출을 보고서 기준으로 맞춘다. 예약 수·박수·1박 평균·취소율·당일 비중·리드타임·객실·국적은 그대로 체크인 예약 기준이다.
다른 기준 숫자를 큰 글씨로 보여 주고 설명을 붙이는 방식은 통하지 않는다. 큰 숫자는 운영자의 기준으로 맞춘다.

## 입력 파일

필수는 내보내기 xlsx와 매핑 JSON뿐이다. 나머지는 없으면 그 기능이 빠지고 결과에 그 사실이 적힌다.

| 옵션 | 형식 | 언제 |
|---|---|---|
| `--prev` | 전 달 `--agg-out` 결과 | 전월 대비 |
| `--sched` | `{"예약번호": {"a": "YYYY-MM-DD", "n": 박수}}` | 체크인 열이 실제 시각일 때. 예정일과 다른 예약만 |
| `--prod` | `{"예약번호": {"p": "상품명", "t": "판매 객실"}}` | 객실 타입 열이 배정 방일 때 |
| `--nat` | `{"예약번호": "KOR"}` | 채널이 넘겨준 국적 코드가 있을 때 |
| `--billing` | `{"total":원, "parts":[["객실",원],…], "conditions":"", "fetched_at":"", "lines":[{"id":예약번호,"acc":거래처,"stay":"MM/DD~MM/DD","b":그 달 보고서 금액,"why":"next"}]}` | 보고서 대조. `lines`는 금액이 다른 예약만 |
| `--billing-acc` | `{"cur":{거래처:원}, "prev":{거래처:원}, "cur_total":원, "prev_total":원, "conditions":"", "fetched_at":""}` | 매출을 보고서 기준으로 |
| `--findings` | `["핵심 문장", …]` | 대시보드 「이번 달 핵심」 |

`why` 코드: `next` 다음 달까지 이어진 숙박 · `prev` 전달에 들어와 이번 달까지 묵은 손님 · `walkin` 다음 달 1일 새벽 워크인 · `late` 말일 밤 손님의 다음 달 1일 새벽 입실 · `early` 전달 말일 밤 손님의 1일 새벽 입실 · `etc` 그 밖.

전월을 내보내기 없이 맞추려면 지난달의 `--agg-out` 파일을 보관해 둔다.

## 매핑 JSON

| 키 | 뜻 |
|---|---|
| `columns` | 표준 항목 → 내 PMS 열 이름. 필수: 예약 번호·거래처·체크인·체크아웃·예약 생성일·예약 상태, 금액(`총 청구 금액`+`잔액` 또는 `예약 금액`) |
| `values` | `stay` 숙박을 뜻하는 값 · `cancel_keywords` 취소·노쇼 판별어 · `channel_booking` 채널 예약을 뜻하는 값 |
| `channels` | 거래처 판별 규칙. `match` 정확히 일치, `contains` 포함. `group` 대분류, `basis` 입금가/판매가/실수령/확인필요 |
| `channels[].commission·coupon_burden·vat` | 숙소 입력값. [채널구분표] 메모에 그대로 보여 준다. **계산에는 쓰지 않는다** |
| `corporate_accounts` | 기업·기관 거래처 이름 |
| `room_types`, `base_room_type` | 객실 표시 순서, 판매→배정 표의 주력 객실 (비우면 건수 순) |
| `product_families` | 상품 묶음. `name`, `contains`, `after_rooms` |
| `hotel_name`, `month`, `sheet`, `header_row` | 숙소명, 기준 월, 시트, 열 이름이 있는 줄 |

고객 이름·연락처로 보이는 열을 매핑하면 스크립트가 멈춘다. 매핑하지 않은 열은 읽은 즉시 버린다.

## 만들기

```bash
python scripts/sales_report.py --input 예약.xlsx --config mapping.json --out 분석.xlsx \
    --month YYYY-MM --prev prev.json --summary summary.json --agg-out agg.json
# summary.json 을 읽고 핵심 발견을 findings.json 으로 쓴 뒤 --findings findings.json 을 붙여 다시 실행
```

- 수식 파일이다. 엑셀로 열면 계산된다. LibreOffice 로 재계산했다면 뒤에 `python scripts/sales_report.py --postfix 재계산.xlsx 최종.xlsx summary.json` 을 돌린다. `KPI 대조: 일치 | 오류 셀: 0` 이 나와야 한다. 재계산 뒤 openpyxl 로 다시 저장하지 않는다(데이터 막대가 사라진다).
- `--min-n 20`: 이 건수 미만 채널은 「기타」로 묶는다. 소규모 숙소는 낮춘다.
- 출력의 `auto`(처음 보는 거래처)가 있으면 [채널구분표] 노란 줄이다. 사용자에게 분류 확인을 요청하고 매핑 JSON에 반영한다.

## 결과 대조 — 이 단계 전에는 끝난 것이 아니다

**분석 매출 + 차이 = 전체.** 이 식이 1원까지 맞아야 한다.

1. PMS의 보고서 합계를 받는다 (예약 합계 또는 청구 보고서).
2. 분석 매출과 금액이 다른 예약을 이유별로 묶는다 → `--billing`.
3. 출력의 `billing_ok: true` 를 확인한다. false면 [청구대조] 탭 2번 마지막 줄의 차이부터 본다.
4. 거래처별로도 `분석 매출 + 차이 = 보고서 거래처 금액` 을 확인한다. 다르면 그 거래처의 잔액 있는 예약부터 본다.
5. [대시보드] 「읽는 법」의 「다른 달 N건 제외」가 몇 건 수준인지 본다. 수백 건이면 `--month` 나 내보내기 기간이 틀린 것이다.
6. 객실 표의 범주가 PMS 객실 타입 수와 같은지 본다. 적으면 어딘가에서 묶인 것이다.
7. 미검증 PMS는 건수·취소 건수·금액 합계를 PMS 화면과 먼저 맞춘 뒤에 해석한다.

보고서 합계를 못 받으면 결과에 「보고서 미대조」라고 적는다. 사용자가 숫자가 이상하다고 하면 말로 버티지 말고 PMS 예약 상세로 확인한 뒤 고친다.

## 핵심 발견 쓰는 법

- 3~6줄, **한 줄에 숫자 2개 이하**, 쉬운 말. 숫자는 summary.json 에서만 가져온다.
- 순서: 전체 매출 변화 → 늘린/줄인 채널 → 예약 행동 변화(당일·미리) → 객실(판매 vs 배정) → 단가·금액 기준 이상 → 확인이 필요한 것.
- 추정은 "~로 보임 (확인 필요)"로 쓴다. 전월 금액이 작은 채널의 증감률은 쓰지 않는다.
- 금액 표기는 KPI와 같게 만 원 단위로 통일한다.

## 지켜야 할 것

- **객실 타입은 묶지 않는다.** PMS 타입을 그대로 쓴다. 묶음이 필요해 보이면 먼저 묻고, 묶더라도 타입별 표를 기본으로 둔다.
- **금액 기준이 채널마다 다르다.** 입금가·판매가·실수령을 섞어 1박 평균을 비교하지 않는다. 같은 기준끼리만 본다. 금액 패턴으로 수수료를 추정했다면 "추정"이라고 적는다.
- **수수료·쿠폰 부담·부가세는 숙소마다 다르다.** 다른 숙소의 값을 쓰지 않는다. 비어 있으면 「미확인」이다.
- 금액 0원 숙박(단체 미정산·무료)은 1박 평균에서 빠진다. 스크립트가 「읽는 법」에 건수를 적는다.
- 받은 돈과 예약 금액이 다른 예약은 「읽는 법」에 적힌다. 환불·추가 수납 확인으로 알린다.
- 국적은 채널이 넘겨준 코드만 쓴다. 이름으로 추정하지 않는다.
- 월 분석의 최종본은 **달이 끝난 뒤** 받은 내보내기로만 만든다. 말일이 빠지면 대시보드에 표시된다.
- 같은 달의 예전 판은 이름에 `_쓰지않음` 을 붙여 분리한다. 옛 판을 열어 보고 숫자가 틀렸다고 하는 일이 생긴다. 지적을 받으면 어느 판을 열었는지 먼저 확인한다.
- 셀에 넣는 설명 글은 `=` 로 시작하지 않는다.
- 파일 다운로드는 사용자 허락을 받고 한다. PMS 로그인·인증은 사용자가 직접 한다.

## 개인정보

- 고객 이름·연락처·이메일은 입력과 결과 어디에도 넣지 않는다. 화면 텍스트를 통째로 읽는 도구를 PMS 화면에 쓰지 않는다.
- **재방문 판단**: 이 스크립트는 재방문을 계산하지 않는다. 요청받으면 PMS의 재방문 표시나 PMS 안의 집계를 쓰고, 결과에는 **건수와 비율만** 남긴다. 이름·전화번호·예약번호를 대화·보고서·파일에 출력하지 않는다. OTA가 가린 이름(김*수)으로 사람을 세지 않는다.
- 결과 엑셀의 [원본]·[청구대조] 탭에는 예약번호와 객실 호수가 있다. 외부에 공유할 때는 이 탭을 뺀다.
- 토큰·인증 헤더는 출력하지 않는다.

## 출력 형식

1. **확인한 자료와 시점** — 내보내기 기간, 매핑(검증/미검증), 쓴 보정 자료
2. **이번 달 핵심** 2~3줄
3. **대조 결과** — 분석 매출 + 차이 = 보고서, 일치 여부
4. **확인이 필요한 것** 1~2개 — 자동 분류 거래처, 금액 기준 미확인 채널, 잔액 있는 예약
5. **저장 위치**

표와 숫자 나열은 엑셀에 둔다.
