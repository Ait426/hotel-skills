# 숙소 점검 — 영역별 절차 · 합격 기준

"점검해줘", "현황 봐줘", "뭐가 부족해"에 쓴다. 입금가 계산(`pricing.md`)과 별개로 노출 점수·후기·콘텐츠·요금 경쟁력·프로그램을 훑는다.
결과는 `property.json` 의 `audit[]` 에 한 줄씩 남기고 콘솔 「점검 결과」 카드로 낸다.

**조회만 한다.** 등록·생성·삭제·비활성화 버튼은 누르지 않는다. 기준값(점수 단계, 등록 기한, 혜택 금액)은 숙소·시기마다 다르니 **화면 문구를 그대로 옮긴다.**

## 0. 이동과 읽기

주소 앞부분은 `https://apps.expediapartnercentral.com` 이다. 파트너센트럴은 주소로 바로 이동해도 세션이 유지된다.
`/supply/…` 화면은 `?propertyId={htid}`, `/lodging/…` 화면은 `?htid={htid}` 를 붙인다.

| 영역 | 경로 | 메뉴 |
|---|---|---|
| 홈 현재 성과 | `/supply/home` | 홈 |
| 노출 순위 요인 | `/supply/search-sort-factors` | 홈 → 노출 순위 「보기」 |
| 요금 경쟁력 피드백 | `/supply/competitive-opportunities` | 객실 및 요금 → 요금 및 예약 가능 객실에 대한 피드백 |
| 기회 목록 | `/supply/opportunities-hub` | 판매 증진을 위한 기회 |
| 숙박 시설 세부 정보 점수 | `/supply/property/overview` | 숙박 시설 세부 정보 → 개요 |
| 사진·객실 설명 | `/lodging/photos/gallery/gallery.html` | 숙박 시설 세부 정보 → 사진 |
| 투숙 후 이용 후기 | `/supply/reviews/post-stay-reviews` | 고객과의 관계 |
| 객실·요금제 | `/lodging/prodcreation/manageRoomAndRate.html` | 객실 및 요금 → 객실 유형 및 요금제 |
| 취소 정책 | `/lodging/cancelpolicy/managecancellationpolicies.html` | 객실 및 요금 → 취소 정책 |
| 엑셀러레이터 | `/lodging/accelerator` | 마케팅 |
| TravelAds | `/supply/travelads` | 마케팅 |
| 요금 자동 매칭 | `/lodging/auto-rate-match/index.html` | 객실 및 요금 |

- 왼쪽 메뉴 하위 항목은 실제 마우스로 펼쳐야 링크가 생긴다. **아래 항목부터 펼치면** 위 항목 좌표가 밀리지 않는다.
- 읽기는 `__epcText()` 로 한다. 왼쪽 메뉴 글자를 빼고 이메일·긴 번호를 가린다.
- **메뉴의 담당자 연락처(숙소 관리자·마켓 매니저 이메일)는 결과물에 적지 않는다.** 링크를 통째로 수집하면 같이 나온다.
- 화면이 늦게 뜬다. 6~10초 기다린 뒤 읽고, 글자가 짧으면 한 번 더 기다린다. 취소 정책처럼 본문 일부가 iframe 인 화면이 있다.
- **예약·메시지·후기 목록 화면은 본문 통째 읽기 금지.** 후기는 `__epcReviewHead()` 로 목록 앞부분만 읽는다.

## 1. 노출 순위 요인 — `search-sort-factors`

평균 정렬 순서, 상위 노출 비율, 그리고 두 점수를 적는다.

| 점수 | 볼 것 |
|---|---|
| 고객 경험 | 일일 점수, 항목별(청결도·시설 상태·체크인·편의 시설·직원) /5 와 「주의 필요」 표시, 예방 가능한 재배치·취소·환불 % |
| 상품 강도 | 일일 점수, 하위 항목(요금 및 예약 가능 객실 피드백, 숙박 시설 세부 정보) 점수와 경쟁사 중 순위 |

같은 화면의 단계별 혜택(예: VIP Access 같은 상위 단계)은 **요건 문구와 현재 달성률**을 그대로 옮긴다. 「주의 필요」가 붙은 항목은 전부 `audit[]` 에 넣는다.

합격: 「주의 필요」 0개, 다음 단계 요건까지의 차이를 적었을 것.

## 2. 요금 경쟁력 — `competitive-opportunities`

상품 강도가 낮으면 여기부터 본다. 관찰 결과의 분류(객실 유형·요금제 / 프로모션 / 요금)와 건수, 「반복되는 문제」 표시, 객실 유형 연동 상태를 적는다.

- 「다른 사이트에서 더 낮은 요금」은 **다른 채널 직판과 협력업체(재판매) 요금**이 섞여 있다. 협력업체 요금이면 우리 요금을 내리기 전에 유통 경로를 확인한다.
- 「누락된 객실 유형」은 다른 사이트에만 있는 객실이 익스에 없다는 뜻이다. 객실 목록(6장)과 대조한다.
- 요금 자동 매칭 등록 제안은 요금을 자동으로 내리는 기능이다. 입금가 하한과 같이 판단하고 등록 버튼은 누르지 않는다.

합격: 반복되는 문제 0건, 협력업체 요금 문제의 원인 파악.

## 3. 숙박 시설 세부 정보 — `property/overview` · `photos/gallery`

세부 정보 점수(/100)와 「다음 단계」 개선 항목을 적는다.
사진 화면에서는 범주별 사진 유무와 **객실 설명의 「알아둘 사항」**을 읽는다. 객실 설명은 손님에게 그대로 노출되는 문구다.

**객실 설명 이상 문구를 찾는다.** 예: 모든 객실에 「침대 시트 제공 안 됨」 같은 문구가 붙어 있으면 객실 용품 설정이 잘못된 것일 수 있다. 몇 개 객실에 붙었는지 세어 적는다.

합격: 개선 항목 0, 객실 설명에 사실과 다른 문구 없음.

## 4. 이용 후기 — `post-stay-reviews`

`__epcReviewHead()` 로 답변 대기 건수를 읽는다. 항목별 점수는 1장의 고객 경험 항목이 같은 역할을 한다.

합격: 답변 대기 0건, 고객 경험 항목에 「주의 필요」 없음.

## 5. 프로그램·비용 — `accelerator` · `travelads` · `auto-rate-match`

| 프로그램 | 볼 것 |
|---|---|
| 엑셀러레이터 | 활성 건의 체크인 기간, 종료일, 수수료 %, 판매 투숙일수, 예약 금액. 수수료 %는 입금 계수의 a 와 맞아야 한다(`pricing.md`) |
| TravelAds | 운영 여부. 소개 화면만 나오면 미운영이다 |
| 요금 자동 매칭 | 등록 여부, 등록 혜택과 마감일 |

- **종료일이 먼 미래인 엑셀러레이터**는 끄지 않는 한 계속 수수료가 붙는다. 입금 계수와 함께 보고한다.

## 6. 객실·요금제·취소 정책 — `manageRoomAndRate` · `cancelpolicy`

활성·비활성 객실 수, 객실별 판매가와 활성 요금제 수를 적는다. 취소 정책 화면에서 활성 정책 수, 기본 정책 내용, 그 정책에 묶인 활성 요금제 수를 적는다.

- 다른 채널보다 객실이 적으면 2장의 「누락된 객실 유형」과 연결해 본다.
- 환불불가 요금제가 있어야 하는데 활성 정책이 하나뿐이면 환불불가 상품이 실제로 있는지 고객페이지에서 확인한다.

## 7. 기회 목록 — `opportunities-hub`

제목과 한 줄 내용을 옮긴다. **전부 실행하라는 뜻이 아니다.** 할인·프로모션 제안은 `payout.py check` 로 입금가와 목표를 먼저 계산한다.

## 기록 형식 — `audit[]`

```json
{ "area": "노출", "item": "상품 강도", "value": "54/100 (요금 피드백 경쟁사 중 4위)", "status": "bad",
  "rule": "2단계 80점, 3단계 85점", "action": "요금 경쟁력 피드백의 반복 문제부터 확인", "source": "노출 순위 화면" }
```

`status`: `ok` 합격 · `warn` 주의 · `bad` 위험 · `unknown` 못 읽음. 위 값은 형식 예시다.

## 아고다 스킬과 같은 산출물 — 기록 칸

점검이 끝나면 `audit[]` 말고도 아래 칸을 채운다. 콘솔이 「현재 설정 · 발견 사항 · 프로그램 · 콘텐츠 · 요금제 · 노출가 실측」 카드로 낸다. 칸 이름은 아고다 스킬과 같다.

| 칸 | 어디서 읽나 | 무엇을 적나 |
|---|---|---|
| `findings` | 아래 영역에서 나온 결론 | 심각도(high·med·info) · 근거 · 정정 |
| `programs` | 엑셀러레이터 · TravelAds · 요금 자동 매칭 · 노출 순위 화면의 단계별 혜택 | 설정 가능 범위(예: 엑셀러레이터 % 선택지)와 현재 설정을 나눠 적는다 |
| `content.photos` | 사진 화면 | 전체 장수, 범주별 누락, 저화질 표시 |
| `content.reviews` | 투숙 후 이용 후기 (`__epcReviewHead`) · 노출 순위의 고객 경험 항목 | 점수, 항목별 점수, 답변 대기 건수 |
| `content.mapping` | 객실 유형 및 요금제 · 요금 경쟁력의 「누락된 객실 유형」 | 채널 매니저와 연결된 객실 수 / 전체, 누락 객실 |
| `ratePlans` | 객실 유형 및 요금제 · 취소 정책 화면 | 요금제명 · 객실 수 · 취소 정책 · 상태 |
| `measurements` | 고객 페이지 객실별 금액 (`__customer`) | 날짜 3개 이상. 입력값은 그날 달력요금 |

- `findings[]` 는 결론이다. `{"title", "severity", "detail", "evidence", "revised"}`. **실측은 `evidence`, 판단은 `detail`** 에 나눠 적는다. 판정이 뒤집히면 `revised` 에 이전 판정과 정정 사유를 남긴다.
- `programs[]` 는 `{"name", "status", "range", "setting", "note", "verified"}`. 화면에서 못 읽은 범위는 `null` 이다. 일반 구조를 그 숙소 값처럼 적지 마라.
- `content` 는 `photos{total, lowRes, untagged, note}` · `reviews{score, count, unanswered, detail{}, compare{}, note}` · `mapping{mapped, total, unmapped, note}`. 숫자 칸에 글자를 넣지 않는다.
- `ratePlans[]` 는 `{"name", "id", "rooms", "base", "policy", "sold", "status"}`. 가격표(요금제 배수·요금)와 다른 것이다. `sold` 가 0이면 `--check` 가 알린다.
- `measurements[]` 는 `{"label", "condition", "input", "shown", "expected", "tolerance"}`. **날짜 3개 이상**을 재서 화면값 ÷ 입력값 비율이 0.001 안에서 맞으면 공식이 선형으로 확인된 것이다. 조회 조건(국가·기기·박수·인원·로그인)을 `condition` 에 적는다.
- `promoGroups[]` 는 **중복 규칙을 계산기에 넣는 칸**이다(아고다 `promotions.groups` 와 같은 역할). `{"name", "mode", "items": [{"name", "pct", "on", "tag"}]}`. `mode` 는 `locked`(항상 적용) · `single`(그룹에서 하나만, 라디오) · `multi`(누적, 체크박스). 켤 수 없는 조합을 계산기가 애초에 못 만들게 이 스킬의 `pricing.md` 중복 규칙대로 그룹을 짠다. 하나만 붙는 그룹에 실제로 2개가 켜져 있으면 `on` 은 하나에만 주고 나머지는 `tag` 에 「적용 중」을 적는다.
- `commissionParts[]` 는 **수수료 조합 비교 칸**이다(아고다 `commission.parts` 와 같은 역할). `{"name", "kind", "pct", "options"}`. `kind` 는 `base`(손님 결제액에서 차감) · `accel`(세전 금액에서 차감). `options` 에 화면의 선택지를 넣으면 드롭다운으로 바꿔 가며 입금가를 비교한다. **pct 를 모르면 null 대신 항목을 뺀다.** 광고비처럼 입금가 공식 밖의 비용은 넣지 않는다.
- `summary[]` 는 맨 위 요약 칸 `{"label", "value", "note"}` 이다. 수수료·계수처럼 그 숙소의 핵심 숫자를 넣는다. 적용 중 프로모션 수·발견 사항·점검 건수·하한은 자동으로 붙는다.
