# 아고다 프로그램·캠페인 지도

무엇이 어떻게 적용되고, 누가 돈을 내고, 무엇을 주고, 언제 쓰는가.
출처: `/ko-kr/app/mnc/{id}/partner-programs-hub` · `/ko-kr/app/mnc/{id}/campaign/list`.
**숙소별 실측치는 여기 없다 — `properties/` 를 봐라.**
본문의 %는 구조를 설명하려는 관측 예시다. **요율·적용 여부는 숙소마다 다르니 포털에서 다시 읽어라.**

목차
1. 돈이 나가는 세 갈래
2. 프로그램 12개
3. 프로모션 종류 6가지
4. 상황별 처방
5. 숙소마다 확인해야 하는 것

## 1. 돈이 나가는 세 갈래

섞으면 계산이 틀린다. 어느 갈래인지부터 판정하라.

| 갈래 | 무엇 | 고객가 | 입금가 | 계산 위치 |
|---|---|---|---|---|
| **① 요금 할인 (Σ)** | 메가세일·시즌·타겟팅·알뜰·OCC·Maximum Gain | 내려감 | 내려감 | `CMS × (1−Σ)` |
| **② 수수료 (보수)** | 계약 수수료 + AGP + AGX (요율은 숙소별) | 그대로 | 내려감 | `× (1−보수)` |
| **③ 광고 비용** | 광고 숙소·부킹홀딩스 광고 (CPC) | 그대로 | 영향 없음 | 공식 밖 (크레딧/청구서) |

### 비용은 전부 숙소가 낸다 — 추측하지 말고 예약으로 증명해라

이 스킬을 만든 조사에서는 실제 예약 여러 건에서 `입금가 = CMS × (1−Σ) × (1−보수)` 가 원 단위로 맞았다.
아고다가 할인을 한 푼이라도 보태고 있다면 입금가가 공식보다 **높게** 나와야 하는데,
그런 건이 하나도 없었다. **새 숙소에서도 실제 예약 1~2건으로 같은 대조를 먼저 해라.**

**아고다가 대는 건 돈이 아니라 자기 채널의 노출이다** — 배너, 랜딩 페이지,
소셜 미디어, 검색 순위, 제휴망. 그래서 같은 10%를 쓸 거면 아고다 주최 캠페인이
자체 할인보다 낫다. 노출이 공짜로 딸려온다.

쿠폰 예외: 소비자 페이지에 쿠폰(AGODA_SPONSORED) 할인이 한 번 더 붙어 보이는데
그 예약의 프로모션 내역에는 없는 경우가 있다. 아고다 부담으로 정리됐으나
숙소마다 쿠폰 붙은 예약의 내역으로 확인한다.

## 2. 프로그램 12개

### 요금·수수료에 직접 걸리는 것 (6)

**성과 극대화 Maximum Gain** — ① · Dynamic / Static 택일
Booking Holdings 제휴 네트워크(10,000개+ 파트너)용 요금. Dynamic 플랜이면 예약마다 MG 할인이 자동으로 붙는다
(관측 예: 35%. 숙소마다 다르다).
포털 문구: "참여를 위한 추가 비용이나 서류 작업이 없으며" — **수수료가 없는 대신 할인 자체가 비용.**
아고다 주장 실적: 룸나잇 +68%, 수익 +34%, 취소율 −28%.
**성과 극대화 = Beds Network.** 두 플랜 중 **택일**이다 — Dynamic(Σ에 MG %가 들어간다) 또는 Static(순수 네트 요금). **끄는 게 아니라 Static으로 바꾸는 것이다.** on/off 토글은 없다. Σ 계산은 항상 여기서 시작하라.
Static 요금대는 `staticPlanDiscount` 슬라이더를 0~100 으로 훑어 객실별로 읽어라 (숙소마다 다르다).
미매핑 파트너 객실이 다른 사이트에 뜨는 것도 이 네트워크 때문이다.

**MG 화면에는 % 가 안 적혀 있다.** 실적용 %는 실제 예약의 `프로모션 내역` 모달에서 읽어라.

**아고다 성장 프로그램 AGP** — ② · 예약당 % 과금
실적(노출·순위·룸나잇·수익)은 `/campaign/list` 에서 읽는다. 여행객 검색 인사이트가 무료로 딸려온다.

**⚠ 화면 두 개가 서로 다르게 말한다.** 프로그램 허브 카드는 `시작하기`(미적용)로 뜨는데
캠페인 목록에는 과금 중으로 나오는 경우가 있다. **캠페인 목록 쪽을 믿어라** — 실제 과금 기록이다.

**아고다 성장 익스프레스 AGX** — ② · 예약당 % 과금 · 기간 지정
캠페인 목록에서 이름·%·기간·실적을 읽는다. 설정 가능 범위(%)는 캠페인 **상세**로 들어가
`[role=slider]` 의 `aria-valuemin`/`aria-valuemax` 를 읽어야 한다 — 목록에는 현재값만 있다.
개시일이 미래면 **그날부터 보수가 그만큼 올라간다.** 보수 역산할 때 개시 전/후 예약을 섞지 마라.

**타겟팅 프로모션** — ① · 지역/플랫폼/멤버십 카테고리
지역 타겟팅(International Rate / US (IP only) 등)은 고객 IP로 갈린다.
**같은 카테고리끼리는 배타적**이라 여러 개를 켜도 Σ에는 하나만 잡힌다. 켜 두면 사실상 고정비.
주는 것: 타겟 고객군 노출, 캠페인 표식, 전용 랜딩 페이지.

**알뜰 프로모션** — ① · 얼리버드·마감임박·장기투숙 등
조건 맞는 예약에만 붙어서 전체 요금을 안 건드린다. 중복 할인 적용 가능.
주는 것: 캠페인 표식뿐. 노출 증대는 약하다.

**메가 세일 프로모션** — ① · 분기별
주는 것: 아고다의 높은 마케팅 투자, 소셜 미디어 노출, 전체 사용자 여정의 프리미엄 위치,
플랫폼 외부 가시성. **같은 10%를 쓸 거면 여기가 가성비 최고.**
판매(예약) 기간 기준이지 투숙일 기준이 아니다.

### 그 외 (6)

**시즌 프로모션** — ① · 홈페이지 배너 + 전용 랜딩 페이지 + 캠페인 표식
올빼미 세일, 깜짝 할인 수요 특가 등. 할인율이 큰 것(예: 20%)이 많아 CMS 인상이 선행돼야 할 수 있다.

**광고 숙소 (Sponsored)** — ③ · 검색 상위 노출 보장, 주간 단위 캠페인
**요금을 안 깎고 노출만 사는 수단.** 입금가에 영향이 없다. 단가는 견적 화면에서 읽는다.

**부킹홀딩스 광고 숙소** — ③ · 클릭당 지불(CPC)
Booking.com·Priceline·아고다 전반 글로벌 노출, 단일 플랫폼 관리. 단가는 숙소별로 조회.
CPC라 예산 통제는 쉽지만 전환이 안 되면 순손실.

**아고다 인텔리전스 프로그램** — ② · **요금 자동화를 통한 수수료 할인**
★ **보수를 낮추는 유일한 프로그램.** 조사할 가치가 있다.
대가로 요금 결정권 일부를 위임한다. Partner Portal에서 조정 내역 전체 확인 가능하고
요금 조정에 이의 제기도 된다. 할인율은 숙소별로 조회.

**아고다 다이내믹 요금 플러스** — 간접 예약을 직접 예약으로 전환. 조건은 포털에서 확인.

**여행객 검색 인사이트** — AGP 파트너 전용, 추가 비용 없음. AGP를 내고 있다면 안 보면 손해.

## 3. 프로모션 종류 6가지

| 종류 | 걸리는 기준 | 중복 | 노출 혜택 | 판단 |
|---|---|---|---|---|
| 메가세일 | **판매(예약) 기간** | 가능 | 소셜 + 프리미엄 위치 + 외부 | 같은 10%면 최고 |
| 시즌 | 판매 기간(주기적) | 가능 | 배너 + 랜딩 + 표식 | 할인율이 크면 CMS 선행 |
| 알뜰 | 조건(리드타임·박수·점유율) | 중복 가능 | 표식만 | 가장 안전 |
| 타겟팅-지역 | 고객 IP | 서로 배타 | 타겟 노출 + 랜딩 | 켜 두면 고정비 |
| Maximum Gain | 전 예약 자동 | 항상 얹힘 | 제휴망 10,000개+ | Static과 택일 |
| 객실 점유율 | 점유율 + 요일 | 가능 | **없음** | 검산 없이 켜지 마라 (`promotion-rules.md` 6장) |

숙소가 종류별로 몇 개를 보유·적용 중인지는 `properties/{숙소}-promotions.md` 에 적는다.

## 4. 상황별 처방

| 상황 | 1순위 | 왜 | 입금가 |
|---|---|---|---|
| 그냥 가격을 내리고 싶다 | **CMS 인하** | 프로모션 10% ≡ CMS 10% 인하인데 되돌리기가 쉽다 | 선형 |
| 노출만 사고 싶다 (요금 유지) | **광고 숙소 / 부킹홀딩스 광고** | ③갈래라 입금가를 안 건드린다 | 영향 없음 |
| 노출 + 할인 둘 다 | **메가 세일** | 같은 10%에 소셜·랜딩·외부 노출이 붙는다 | −CMS×10%×(1−보수) |
| 비수기 장박 | **장기 투숙 (박수 조건)** | 조건 맞는 예약만 깎인다 | 해당 예약만 |
| 임박 예약을 잡고 싶다 | **마감 임박** | 얼리버드 리드타임 경계 안쪽은 얼리버드가 안 붙어 임박 손님이 오히려 비싸다 | −CMS×할인율×(1−보수) |
| 특정 요일만 채우고 싶다 | **해당 요일 CMS 인하** | 요일 프로모션은 결국 CMS 인하와 같고 관리만 복잡 | 선형 |
| **수수료를 낮추고 싶다** | **아고다 인텔리전스** | ②갈래를 건드리는 유일한 수단 | 보수↓ = 입금↑ |
| 성수기라 올리고 싶다 | CMS 인상 + 프로모션 정리 | Σ가 높으면 CMS를 올려도 체감이 안 된다 | 선형 |

핵심 감각: **프로모션 10%p = 입금가에서 `CMS × 10% × (1 − 보수)` 가 사라진다.**
(보수 18%면 CMS의 8.2%, 보수 20%면 8.0%. `scripts/payout.py table` 마지막 줄이 이 값을 계산해 준다.)

## 5. 숙소마다 확인해야 하는 것

아래는 포털에 숫자가 바로 안 보이거나 숙소·시기마다 달라 **매번 새로 확인**해야 하는 항목이다.
확인 못 했으면 `property.json` 의 `open[]` 에 그대로 옮겨 적는다.

| 항목 | 왜 중요한가 | 확인 방법 |
|---|---|---|
| 광고 숙소 단가 | ③갈래 예산 산정 | 프로그램 허브 → 광고 숙소 |
| 부킹홀딩스 광고 CPC | 동일 | 프로그램 허브 → 부킹홀딩스 광고 |
| **인텔리전스 수수료 할인율** | 보수를 낮출 유일한 수단 | 프로그램 허브 → 인텔리전스 |
| 다이내믹 요금 플러스 조건 | 구조 미파악 | 프로그램 허브 |
| 시즌 "다양함/변동" 할인율 | 목록에 %가 없는 프로모션이 있다 | 켜고 첫 예약의 프로모션 내역 |
| 소비자 페이지 자체 쿠폰 | 아고다 부담으로 정리됐으나 숙소별 확인 필요 | 쿠폰 붙은 예약의 프로모션 내역·정산서 대조 |
| 프로그램 개시 이후 실제 보수 | AGX 등이 개시일부터 실제로 붙는지 | 개시일 이후 투숙분의 정산서 |
