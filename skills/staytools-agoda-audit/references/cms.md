# 채널 매니저 · PMS 읽는 법

아고다 포털 밖의 소스다. 아고다가 들고 있는 요금이 **어디서 온 값인지** 확인할 때 쓴다.
CMS를 안 보면 "이 비율이 왜 이렇지"에서 막힌다 (`pricing.md` 소거법 ③).

**아래 절차는 YFlux PMS · WINGSCMS 를 쓰는 숙소에서 디버깅한 것이다.**
다른 PMS·채널 매니저를 쓰는 숙소는 같은 항목(예약별 입금액 / 상품그룹별·날짜별 요금)을
그 시스템 화면이나 내보내기 파일에서 읽으면 된다. 상품그룹 코드·요금세트 이름은 숙소마다 다르다 —
`properties/{숙소}.md` 에 적어 두고 여기에는 넣지 않는다.

## 3. PMS (YFlux 계열 예시)

```
https://pms.yflux.biz/reservationManagement/integratedSearch
```

ag-Grid를 쓴다. **백그라운드에서도 렌더링된다.**

```js
const heads={};
document.querySelectorAll('.ag-header-cell').forEach(h=>{
  const id=h.getAttribute('col-id');
  if(id) heads[id]=(h.innerText||'').trim().split('\n')[0];
});
const rows=[];
document.querySelectorAll('.ag-center-cols-container .ag-row').forEach(rw=>{
  const o={i:+rw.getAttribute('row-index')};
  rw.querySelectorAll('.ag-cell').forEach(c=>{
    const k=heads[c.getAttribute('col-id')];
    if(k) o[k]=(c.innerText||'').trim().replace(/\n+/g,'|');
  });
  rows.push(o);
});
rows.sort((a,b)=>a.i-b.i);
```

행 이름은 `.ag-pinned-left-cols-container .ag-row`에 따로 있다. `row-index`로 맞춘다.

읽을 것:
- `예약 번호` — `내부번호|아고다예약번호` 형태. 뒤쪽이 아고다 번호다 (대조용으로만 쓰고 결과물에는 남기지 않는다)
- `총 청구 금액` — **숙소 입금가**
- `거래처`, `체크인`, `체크아웃`, `성인`, `예약 생성일`

여러 객실 예약은 행이 객실 수만큼 반복된다. 합산할 때 중복 주의.
PMS 총 청구 금액에 현장 수기 추가분이 섞일 수 있다 — 보수 역산에 쓰기 전에 운영자에게 확인해라.

## 4. WINGSCMS (예시)

```
https://wingscms.com/#/app/cm/cm03_0200   요금관리
https://wingscms.com/#/app/cm/cm03_0600   요금세트 생성
```

ag-Grid. 위와 같은 방식으로 읽는다. 단 **창이 백그라운드면 행이 0개로 나온다** —
포털·PMS와 달리 여기는 화면에 보여야 한다.

### 상품그룹 — 숙소별로 적는다

채널(또는 채널 × 요금제)마다 상품그룹이 따로 있다. 조사할 때 이런 표로 옮긴다.

| 그룹 (예) | 코드 |
|---|---|
| 국내 OTA | (숙소별) |
| 부킹닷컴 | (숙소별) |
| **아고다** | (숙소별) |
| 아고다 조식 요금제 | (숙소별) |
| 익스피디아 | (숙소별) |
| 트립닷컴 | (숙소별) |

### 요금세트 — 채널마다 쓸 수 있는 세트가 다르다

요금세트 컬럼(예: `WEEK, FRI, SAT, SUN, 연말 세트, 시즌 세트 …`)은 전 채널을 합친 목록이다.
**상품그룹마다 쓸 수 있는 세트가 다르다.** 한 채널에서 본 세트가 아고다 그룹에는 없을 수 있다.
아고다에 임시 요금을 걸려면 아고다 그룹에서 쓸 수 있는 미사용 세트를 쓰거나 새로 만들어야 한다.

| 상품그룹 | 쓸 수 있는 세트 |
|---|---|
| (숙소별로 기록) | |

아고다 그룹의 대표 객실 요금을 세트별로 읽어 `property.json` 의 `weekly` · `channels` 에 넣는다.
**요일이 아니라 날짜에 세트가 붙는다** — 같은 일요일도 어떤 주는 SUN 세트, 어떤 주는 WEEK 세트일 수 있고,
성수기에는 시즌 세트가 붙어 값이 다르다. 쓰기 전에 해당 날짜를 직접 읽어라.

**요금관리 그리드에서 아고다 '요금' 입력칸이 disabled 인 경우가 있다.** 값은 요금세트가 정한다.
날짜별로 다른 값을 넣으려면 그 날짜의 요금세트를 바꾸는 방식이다.

### 부가 요금제(조식 등) 상품그룹

아고다 요금제를 `적용 해제`해도 CMS 상품그룹 목록은 그대로 남는다 — **정리 대상**으로 보고한다.
같은 이름의 조식 상품이 다른 채널(예: 트립닷컴)에 따로 있을 수 있다. 채널이 다르면 별개다.

조식 미운영 요일이 있는 숙소는 그 요일 전날 투숙분에 조식 상품이 없는 게 정상이다.
운영 예외는 `properties/{숙소}.md` 의 「사용자가 정한 선」에 적어 두고 판정에 반영한다.
부가 요금제를 유지할지는 `pricing.md` 의 판정 순서(요금제별 Σ 역산 → 실제 예약 유무)로 정한다.
