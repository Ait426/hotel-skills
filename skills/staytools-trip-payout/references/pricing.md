# 공식 · 할인 구조 · 요금제

숫자는 전부 가상 숙소의 형식 예시다. 값은 그 숙소의 자료에서 읽는다.

## 공식

기호: `r` 파생 배수(환불불가·인원별, 해당 없으면 1) · `c` 수수료율 · `Σ` 호텔 부담 할인 합계 · `A` 예약 지급액의 추가 항목

```
P'           = 기준 판매가 × r        ← 고객 페이지 취소선 정가
원래 객실 요금  = P' × (1 − c)          ← 예약 상세 「원래 객실 요금」(이미 수수료를 뗀 값)
최종 객실 요금  = 원래 객실 요금 × (1 − Σ)
지급액         = 최종 객실 요금 − A      ← 예약 상세 「지급액」(입금의 정본)

역산:  기준 판매가 = 목표 ÷ (r × (1 − c) × (1 − 최저경로 Σ))   → 천원 단위 올림
복원:  P' = (실입금 + 할인 합계) ÷ (1 − c)      (추가 항목 A가 찍혀 있으면 A도 더한다)
```

- **할인은 곱셈이 아니라 덧셈이다.** 프로모션 40% + 회원 10% = 50%이지 46%가 아니다 (가상).
- **파생은 곱셈이다.** `r`은 판매가 단계에서 곱하고, 프로모션은 수수료 후 금액에 더해서 뺀다. 둘을 섞지 마라.
- **`A`는 예약 지급액에서 읽는다.** 비율을 공식으로 만들지 마라. 관측된 차감 비율은 예약마다 달랐다.
- **입금의 정본은 예약 지급액이다.** 위 식으로 낸 값은 계산값이다.
- 다른 채널의 계수를 트립에 쓰지 마라. **채널마다 다르다.**

### 계산 예시 (가상 숙소 — 형식만 본다)

기준 판매가 200,000 · r 0.9 · c 15% · Σ 50% (가상)
→ P' 180,000 → 원래 객실 요금 153,000 → 최종 객실 요금 76,500 → **지급액 76,500** (A = 0)
같은 예약에 A 3,000(가상)이 찍히면 → 지급액 73,500

역산 (가상): 목표 70,000 · r 0.9 · c 15% · 최저경로 Σ 50%
→ 70,000 ÷ (0.9 × 0.85 × 0.5) = 183,006.5 → **184,000** (검산 70,380)
반올림해서 183,000을 쓰면 69,997.5로 **목표 미달**이다. 그래서 올림한다.

복원 (가상): 실입금 76,500 + 할인 합계 76,500 = 153,000 → ÷ 0.85 = **P' 180,000** → ÷ r 0.9 = 기준 판매가 200,000

### 레버리지 — 같은 %p라도 Σ가 높을수록 비싸다

`입금 감소율 = 1 − (1 − Σ − Δ) ÷ (1 − Σ)`
예(가상): Δ 10%p는 Σ 20%에서 입금 −12.5%, Σ 50%에서 입금 −20%.

## 호텔 부담 vs 트립 부담

| 호텔 부담 — 입금에서 빠진다 | 트립 부담 — 입금과 무관 |
|---|---|
| 프로모션·캠페인 (상세에 「판매당 비용 계정으로 결제: 아니요」) | 신규회원 할인코드 |
| 회원 할인 TripPlus | 첫 예약 특가 |
| CoinPlus 등 프로그램 차감 (`A`) | 끝전 맞춤 |
| | 손님이 코인으로 결제한 금액 |

- 「판매당 비용 계정」으로 결제되는 항목은 미조사다. 「예」로 표시된 프로모션을 만나면 **미확인**으로 적는다.
- CoinPlus의 차감은 **손님에게 새로 적립되는 보너스 코인 값을 호텔이 내는 것**이고, 손님 결제가를 내리지 않는다.
- 트립 부담 항목을 구분한 근거: 한 숙소 관측으로 실예약 약 1,000건의 Promotion 칸에 「첫 예약」 류가 한 건도 없었다.

## Σ 산정 — 이 순서로 묻는다

```
유입 경로 → 적용 국가 → 대상 객실·요금제 → 회원 여부 → 프로그램 차감
```

| 순서 | 묻는 것 | 어디서 읽나 |
|---:|---|---|
| 1 | **어느 경로로 들어왔나** — Package 대상(트립에서 항공·기차·티켓 등을 예약한 손님)인가, 일반 검색인가, 연박(최소 숙박) 조건을 채웠나 | 예약 할인 내역 / 프로모션 Details |
| 2 | **그 손님 국가가 적용 목록에 있나** — 이름이 아니라 목록으로 판단 | Details 「적용 국가 및 지역」 |
| 3 | **그 객실·요금제가 대상인가** — 「전 객실」로 단정 금지 | Details 「Room types and rate plans」 |
| 4 | **회원인가** — 회원 가산 `m`을 더한다 (프로필의 값) | 예약 할인 내역, 프로그램 화면 |
| 5 | **프로그램 차감이 있나** — Σ가 아니라 `A`로 따로 뺀다 | 지불 정보 「추가 요금」 줄 |

한 숙소 관측: 같은 객실·같은 날짜가 경로에 따라 다른 지급액으로 들어왔다. 3번을 빼먹어 영향 규모를 몇 배 틀린 적도 있다.
어떤 프로모션의 대상이 아닌 객실은 그 손님에게 Σ가 `0` 또는 `m`까지 내려간다.

**겹치지 않는 할인끼리는 큰 쪽 하나만 걸린다. 비교는 「프로모션 + 회원」 합계로 한다.**
한 숙소 관측: 캠페인보다 얕은 기본 할인이 회원 가산을 더하자 캠페인보다 커져서 회원 예약의 입금을 깎았다.

## 프로모션 유형 · 중복 규칙

| 묶음 | 유형 | 메모 |
|---|---|---|
| 특정 그룹 | Mobile Rate · 항공+호텔 · XPOS | XPOS는 지역 지정 |
| 기본 | 기본 할인 · 사전 예약 · 라스트 미닛 · 연박 혜택 · 당일 밤 특가 · 객실 다량 예약 할인 | 당일 밤 특가에는 국적 구분이 없다 |
| 파격 특가 | 기간 한정 특가 | |
| 캠페인 | Country Banner 등 트립 마케팅 캠페인 | 기간·시장 한정, 최소 할인 15~20% (시점값, 다를 수 있음) |
| Package | 교통 예약 손님 | 수정 화면 설명 기준. 적용 국가 제한 없음으로 관측 |
| 프로그램 | TripPlus · CoinPlus · 특전 · Smart Offer 등 | 프로모션 화면 밖, 비즈니스 기회 메뉴 |

**중복 규칙은 외우지 말고 화면 원문을 읽는다.** 위치: 프로모션 > My promotions > Details > Modify >
「Discounts and stay dates」 아래 「Promotion stacking rules」. 유형마다 목록이 다르다.

| 기준 프로모션 | 겹침 | 안 겹침 (큰 쪽 하나만) |
|---|---|---|
| XPOS 화면 원문 | TripPlus, CoinPlus, Basic Deal, Early Bird, Last Minute, Offer for Tonight, Minimum Stay | Packages, campaigns, Mobile Rate |
| 연박 혜택 화면 원문 | TripPlus, CoinPlus, XPOS, 모바일 요금 | 패키지, 이벤트, 얼리버드, 라스트 미닛, 당일 특가, 기본 할인 |
| Package 수정 화면 | CoinPlus, TripPlus | 배너, XPOS |

(시점값, 다를 수 있음)

- 캠페인과 Package는 같이 붙지 않는다. 한 숙소 관측: 예약 650건 전수에서 공존 0건.
- 연박 혜택이 캠페인을 이기려면 캠페인보다 커야 한다. 작게 걸면 그 손님에게 효과가 없다.
- 깊은 연박 혜택에 회원 가산이 더해지면 최저 경로가 바뀐다. 한 숙소 관측: 실예약에서 연박 + 회원 합산을 확인했다.

### ★ 「확인 필요」 — 단정하지 말고 숙소별로 확인한다

| 항목 | 지금 아는 것 | 확인 방법 |
|---|---|---|
| **캠페인 + 회원 중복** | 프로모션 + 회원 합산은 확인됐다. 캠페인 + 회원은 한 숙소 관측으로 650건 중 4건뿐 공존(캠페인 단독 193건)이라 규칙이 안 풀렸다 | 예약 엑셀 Promotion 칸에서 캠페인이 찍힌 건의 회원 동반 여부를 세고, 동반 건의 할인 내역을 펼쳐 합이 더해졌는지 본다 |
| **프로모션 적용 기준 (IP / POS / 거주국)** | 화면에는 「적용 국가 및 지역」만 있다. 무엇으로 판별하는지 근거가 없다 | 트립에 문의한다. 답이 없으면 「손님 국가 미확인」으로 표시하고 실제 찍힌 할인으로만 말한다. 한국에서 조회한 화면으로 다른 국가 가격을 말하지 마라 |
| **항공+호텔과 Package의 관계** | Package의 대상 손님은 수정 화면 설명으로 확인됐다. 카탈로그의 「항공+호텔」 유형과 같은 것인지는 근거가 없다 | My promotions의 유형 표시와 카탈로그 항목을 대조하고, 안 풀리면 트립에 문의한다 |
| **회원 할인이 플랫폼 고정값인가** | 등급별 전부 10%로 관측 (시점값, 다를 수 있음). 화면에 수정 버튼이 있어 고정인지 불명 | TripPlus 화면에서 읽어 프로필에 적는다. 고정값으로 쓰지 않는다 |
| **넷가·후불·VCC 계약** | 미검증. 이 스킬의 공식은 판매가 입력·선결제에서만 확인됐다 | 재무 메인에서 결제 방식을, 요금제 목록에서 요금 모드를 읽는다. 다르면 실예약 지급액으로 공식을 새로 검증하기 전까지 계산값을 내지 않는다 |
| **부가세 처리** | 한 숙소 관측: 지불 정보의 부가가치세 줄이 지급액에 가감되지 않았다. 세금 규정 화면은 미조사 | 호텔 정보 › 세금 규정과 정산 명세서를 읽고 세무 담당자에게 확인한다 |
| **조식 1인 요금의 출처** | 고객 페이지에 우리 요금제에 없는 조식 1인이 뜬다. 후보는 호텔 정책의 조식 단가, 또는 Pricing per guest 규칙. 한 숙소 관측에서 두 후보가 같은 값을 내 구분되지 않았다 | Pricing per guest 규칙을 읽고, 두 후보의 값이 달라지는 날짜의 고객 페이지 정가를 비교한다. 값을 시험 삼아 바꾸지 않는다 |

## 요금제 · 파생 · 인원별

| 구분 | 어떻게 움직이나 | 어디서 확인 |
|---|---|---|
| 환불불가 파생 | 기준 요금제 × `r`. 상태·제한을 승계할 수 있다 | 요금제 목록의 파생 규칙 |
| 인원별 요금 | 객실 × 요금제별 규칙. `r`에 곱해 넣는다 | **Calendar → 「Pricing per guest」** (요금제 편집 화면에는 없다) |
| 조식 요금제 | 숙소가 정한 값. 프로필의 규칙을 따른다 | 달력 |
| 트립 생성 조식 `[FD]` | 우리 요금제 목록에 없다. 기준 요금제에 정액을 얹어 트립이 만든다 | 고객 페이지 |

- **「안 변한다」를 주장하려면 입력값이 다른 날짜 두 개 이상을 본다.** 한 숙소 관측: 주중만 봐서 고정값으로 적은 인원별 요금이 실제로는 비율이었다.
- **달력에 값이 있어도 팔리는 건 아니다.** 판매 토글을 같이 본다.
- 인원을 바꿔 검색한다. 한 숙소 관측: 성인 수에 따라 뜨는 요금제가 달라졌다.

### `[FD]` 조식

- 숙소가 끌 수 있는 스위치를 eBooking 안에서 찾지 못했다. 한 숙소 관측: 요금제·달력·패키지·Connectivity·호텔 정책·도움센터를 전수로 봤다.
- 찾다가 막히면 더 파지 말고 트립 문의로 넘긴다.
- 한 숙소 관측: 우리 조식 요금제가 `[FD]`보다 싸면 `[FD]`가 화면에서 사라졌고, 우리 조식을 판매 중지한 날에는 `[FD]`가 그 자리에 떴다.
- 구분: 우리 요금제 목록에 없고, 취소 기한이 우리 정책과 다르며, 가격이 「기준 요금제 + 정액」이다. 얹는 금액은 프로필에 적는다.
- 조식을 운영하지 않는 날에 `[FD]`가 뜨면 **못 주는 상품이 팔린다.** 호텔 정책의 조식 운영 요일 화면을 근거로 트립에 제기한다.
