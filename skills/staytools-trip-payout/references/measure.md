# 입금가 확인 · 실측 원장 · 데이터 수집

## ★ 입금가 확인 경로

| 고객 페이지에 뜨는 것 | 안 뜨는 것 |
|---|---|
| 취소선 정가 · 할인 줄 · 손님 결제 | 수수료 · 프로그램 차감 · **지급액** |

**예약 상세:** 예약 관리 → 예약 클릭 → 드로어의 **지불 정보** → 입금가 뷰

- 「원래 객실 요금」 = **수수료를 뗀 값**. 판매가로 읽으면 수수료가 0%로 보인다
- 「할인 +N」을 눌러야 줄별로 나온다. 펼치기 전에는 합계뿐이다. 할인이 하나면 처음부터 줄로 보인다
- 여러 건은 `scripts/snippets.js` 의 `__payments` 로 읽는다. 지급액은 목록 행 금액과 맞아야 쓴다
- 「추가 요금」 줄 = 프로그램 차감. 입금이 공식보다 낮으면 여기를 본다
- 「자세히 보기」 = 날짜별 명세. **다박 예약은 밤마다 스택이 다를 수 있어** 합계로 %를 역산하지 않는다

**"입금가"라고 쓰려면 여기까지 와야 한다.** 그 외는 계산값이다.

### 「입금가가 이상하다」 진단 순서

1. 예약 상세 할인 줄(또는 예약 엑셀 Promotion 칸)을 본다
2. 할인 합계 ÷ 원래 객실 요금으로 %를 확인한다
3. 복원 공식으로 P'를 구해 그 날짜의 달력값과 대조한다
4. **P'가 맞으면 요금 문제가 아니라 할인 문제다.** 고치는 곳이 다르다 (달력·채널 매니저 vs 프로모션)
5. 새 할인인지는 My promotions · 캠페인 탭(「수정」= 참여 중, 「지금 가입」= 미참여) · 비즈니스 기회를 본다

### 고객 페이지로 역산할 때 — 취소선 정가와 요금 정보 툴팁만 쓴다

가격 위에 마우스를 올리면 「요금 정보」가 열린다.

- 취소선 정가 = P' (달력 판매가 × r)
- 「특별 할인」 줄 ÷ 정가 = 호텔 쪽 Σ의 점검값. 프로필 Σ와 어긋나면 끝전 맞춤이나 다른 프로모션이 섞인 것이니 예약 지급액으로 확정한다
- **툴팁의 「객실 요금」은 정가가 아니다.** 한 숙소 관측: 정가에서 「부가가치세」 줄을 뺀 값이었다(객실 요금 + 부가가치세 = 취소선 정가). 정가는 취소선에서 읽는다
- 화면 배지의 % 는 Σ가 아니다. 한 숙소 관측: Σ 57%인 객실의 배지가 61%였다. 차이의 출처는 확인 필요이고, 지급액은 예약에서 Σ 57%로 찍혔다
- 신규회원 코드·첫 예약 특가 줄은 트립 부담이다. **쿠폰을 뺀 가격에 (1 − c)를 곱하면 입금을 낮게 잡는다**

예(가상): 정가 200,000 → 특별 할인 −100,000 → 신규회원 코드 −10,000 → 손님 90,000
입금 계산값 = 100,000 × 0.85 = **85,000** (90,000 × 0.85 = 76,500 은 틀린 값)

**파란 판매 표시가에 고정 계수를 곱해 입금을 구하지 마라.** 한 숙소 관측: 표시가 ÷ 정가는 날짜·요금제·계정마다 흔들렸다.
조회 계정이 쿠폰 대상이면 일반 손님과 다른 값이 보인다.

### 실측 원장 — 이런 표로 남긴다

| 예약 | 예약일 | 경로 | 붙은 할인 | P' | 원래 객실 요금 | Σ | A | **지급액** | 공식 차이 |
|---|---|---|---|---:|---:|---:|---:|---:|---:|
| 예약 A (가상) | 당일 | 일반 | 프로모션 40 + 회원 10 | 180,000 | 153,000 | 50% | 0 | **76,500** | 0 |

예약번호와 투숙객 이름은 원장에 남기지 않는다. "예약 A/B"와 예약일로만 가리킨다.

## 데이터 수집

**예약 엑셀이 정본이고, Promotion 칸에 예약 당시 호텔 부담 할인과 CoinPlus 차감이 남는다.** 사라진 과거 프로모션도 여기서 복원된다.

| 규칙 | 이유 |
|---|---|
| 예약일(OrderDate)로만 조회된다 | 「Check-in date」 필터가 보여도 0건이었다 (시점값, 다를 수 있음) |
| 투숙월 집계는 **앞 두 달을 덧붙여** 받고, 맨 앞 달의 해당 투숙이 0건인지 본다 | 예약일 자료는 「그 해에 잔 건」이 아니다 |
| 집계는 확인된 예약만. `Revised` 등 무효 상태는 뺀다 | 예약번호가 달라 중복 제거로 안 걸러진다 |
| 건수는 **CSV 파서로** 센다. `wc -l` 금지 | 칸 안에 줄바꿈이 있다 |
| 한 건 받고 **파일이 생겼는지 확인한 뒤** 다음 건 | 연타하면 브라우저가 사이트 다운로드를 차단하고 에러가 안 뜬다 |
| 「다운로드」는 다운로드 목록에 작업을 만든다. 거기서 행별로 다시 받는다 | 성공 판정은 새 탭이 열렸나, 파일이 생겼나 |
| 파일명에 기간이 없다. 받자마자 이름을 바꾼다 | 작업 시각을 적어 두면 파일명 시각과 맞춰 볼 수 있다 |
| 날짜 범위는 URL 해시(`#filterType=OrderDate&dateValues[0]=…&dateValues[1]=…`)로 지정된다 | 날짜 선택기에 타이핑이 안 먹었다 (시점값, 다를 수 있음) |
| 예약 목록 API(`queryOrderList`)는 `total` 건수만 믿는다 | 오래된 달의 레코드가 에러 없이 빠졌다 |
| 국적 칸이 없다. 이름으로 추정하면 반드시 「추정」이라 쓴다 | 오차가 있다 |

요약 문서가 아니라 **독립적으로 받은 원본끼리** 대조한다. 작은 불일치를 반올림하지 마라.
