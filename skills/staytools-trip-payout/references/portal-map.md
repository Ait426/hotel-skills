# 화면 지도 · 재판매 구분 · 함정

## 화면 지도

**eBooking — `https://ebooking.ctrip.com`** 세션은 ctrip 도메인에 있다(시점값, 다를 수 있음). `ebooking.trip.com`으로 들어가면 로그인 화면이 뜬다.

| 화면 | 경로 | 용도 |
|---|---|---|
| 예약 관리 | `/ebkorderv3` | 목록, 드로어, 지불 정보, 엑셀 |
| 달력 | `/calendar/rateplan` | 판매가·상태·재고. 오른쪽 위 「Pricing per guest」 |
| 요금제 | `/rateplan/rateplanList` | ID·취소 정책·파생 규칙·요금 모드 |
| 일괄 수정 | `/rateplan/bulkGuide` | |
| 설정 기록 | `/rateplan/systemlogv2` | 변경 로그 |
| Connectivity 설정 | `/cm/connectivity/settings` | 채널 매니저 연동 |
| **My promotions** | `/promotion/myOvsPro` | OFF 칸, Details, Logs, Modify |
| 프로모션 카탈로그 | `/promotion/proList` | 유형, 캠페인 탭 |
| CoinPlus | `/promotion/coinPlus/edit` | 「프로젝트 개요」 탭 맨 아래 「거부」가 참여 종료, 「수정」은 할인율 변경 |
| 재무 메인 | `/ebkfinancev2/settlement/financeInfo/home` | 결제 방식, 출금 대기 |
| 선결제 내역 | `/ebkfinancev2/settlement/prepay` | 예약별 지급액 원장, 명세서 |

호텔 계약 ID(재무·프로모션 화면)와 고객 페이지 호텔 ID는 **다른 번호**일 수 있다. 둘 다 프로필에 적는다.
고객 페이지 주소는 프로필에서 읽는다.

## 재판매 구분 — 화면에 뜬다고 우리 요금이 아니다

트립은 같은 객실·같은 식사 조건이면 **제일 싼 공급처 하나만** 보여 준다(한 숙소 관측). 다른 공급처 상품이 더 싸면 우리 요금은 **판매 중지가 아니라 화면에서 숨는다.**

**화면으로만 판별한다. 다른 채널 요금에서 재판매가를 계산하지 마라.** 그런 식은 원본 조사에서 실측과 어긋나 철회됐다.

| 판별 | 우리 요금 | 다른 공급처 |
|---|---|---|
| 요금 행 `data-exposure`의 `rm_taglist` | `AgentRoom` 없음 | `AgentRoom`, `POINTOFORDER` 있음 |
| 가격 툴팁 「요금 정보」 | 「특별 할인」 줄 있음 | 없음 |
| 취소선 정가 | 달력 판매가 × r 과 같음 | 다름 |
| 무료 취소 마감·기한 | 프로필의 취소 정책과 같음 | 다를 수 있음 |
| eBooking 요금제 목록 | 있음 | 없음 |

판별 스니펫은 `scripts/snippets.js` 의 `__resale` 이다. 빈 결과면 판별 불가로 적는다.

**「할인율이 작은 상품」이 보이면 정가가 판매가가 아니라는 신호일 수 있다.** 우리 공식을 대지 말고 위 표로 먼저 가른다.
재판매 예약의 입금 기준은 미확인이다.

### 안 뜨는 이유는 세 갈래 — 먼저 나눈다

| 이유 | 판정 | 어떻게 가르나 |
|---|---|---|
| 저장 안 됨 | 문제 | eBooking 달력의 값 |
| 판매 중지·재고 없음·조건 불일치 | 설정 확인 | 달력 토글·재고, 취소 기한(당일 검색에 무료취소가 안 나갈 수 있다), 인원 수 |
| 다른 공급처에 밀림 | 문제 | 같은 칸의 다른 공급처 상품이 위 표로 판별됨 |

**1박과 2박 화면을 둘 다 연다.** 한 숙소 관측: 판매가 인상 뒤 1박 무료취소 칸만 밀렸고 2박은 그대로였다.

## 함정

| 함정 | 대처 |
|---|---|
| 예약 드로어를 닫지 않고 다음 예약을 누르면 주소의 orderId만 바뀌고 내용은 옛 예약 그대로다 | 드로어 안에 예약번호가 없어 주소로는 확인되지 않는다. 매번 닫고, 목록 행 금액과 드로어 지급액이 같은지 본다 (`__payments`). 한 숙소 관측: 예약 9건이 전부 같은 금액으로 읽혔고 닫은 뒤 다시 읽어 10건 모두 맞았다 |
| 프로모션 드로어에 이전 내용이 DOM에 남아 옛 값을 읽는다 | 드로어 제목으로 골라 읽는다 |
| 「할인 +N」이 스크립트 클릭으로 안 펼쳐진다 | 실제 마우스 클릭으로 펼친다. 합계만 필요하면 펼치지 않아도 된다 |
| 드로어의 지불 정보 뒤에 전화번호 안내가 이어진다 | 「자세히 보기」 앞에서 자른다. 화면 글자를 길이로 자르지 않는다 |
| `__resale` 결과에 조식 선택 금액(예: 10,000원)과 연박 총액이 섞인다 | 첫 금액은 손님가, 다음은 취소선 정가, 2박 이상의 마지막 금액은 총액이다 |
| 프로모션 이름만 보고 판단 | 이름의 %·국가·대상을 믿지 말고 OFF 칸과 Details를 읽는다 |
| 프로모션을 「모든 객실 유형 및 해당 요금제」로 만들면 B2B 요금제까지 들어간다 | 특정 객실 선택 → 「B2C」 체크. 저장 뒤 Details에서 B2C·B2B 개수를 확인 |
| 「높은 할인 알림 — 최종 할인 N%」 | 국가 제한을 무시한 단순 합산으로 관측됐다. 겹친다는 프로모션들의 적용 국가가 실제로 겹치는지 확인 |
| 국가 선택 목록이 전 세계가 아니다 | 5개 지역 55개국 (시점값, 다를 수 있음). 고른 나라를 저장 뒤 다시 읽는다 |
| 프로모션 수정 화면에서 「Back」을 누르면 목록으로 나간다 | 한 페이지 세로 스크롤이다. 아래로 내린다 |
| 할인율 칸에 값이 안 먹는다 | React 칸. 네이티브 setter + input·change 이벤트, DOM값과 React값을 둘 다 대조. 하단 요약이 새 %로 바뀌었는지 확인 |
| 모달이 늦게 뜬다 (15~20초, 시점값, 다를 수 있음) | 화면이 어두워졌으면 눌린 것이다. 다른 데를 누르면 작업이 취소된다 |
| 해제는 여러 단계다: Deactivate → Confirm → 사유 선택 → Deactivate | 중간의 트래픽 감소 수치는 숙소 실적이 아니라 일반 문구로 관측됐다 |
| 고객 페이지에서 `document.body.innerText`가 차단될 때가 있다 | 페이지 텍스트 도구로 읽는다 |
| 연박 검색 목록의 마지막 금액을 박당가로 읽는다 | 「총금액」 앞에서 자른다 |
| 달력 아래쪽 객실이 안 읽힌다 | 스크롤해 lazy-load 시킨 뒤 읽고, 날짜 헤더로 열을 먼저 잡는다 |
| 프로그램 대시보드의 기간 값이 서로 모순된다 | 기간 수치로 추세를 읽지 말고 예약 단위 차감액을 본다 |
| 로그인 여부를 없는 페이지에서 판정 | 로그인이 필요한 실제 화면(My promotions 등)으로 판정 |
| 메시지·문의 채팅창이 열렸다 | 타이핑하지 않는다. 문의 발송은 사용자가 정한다 |
