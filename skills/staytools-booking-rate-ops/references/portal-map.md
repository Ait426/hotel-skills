# 화면 지도 · 조작 절차 · 함정


## 접속 정보 — 프로필에서 읽는다

| 대상 | 주소 |
|---|---|
| 익스트라넷 | `admin.booking.com` (hotel_id = 프로필의 숙소 ID) |
| 소비자 페이지 | `booking.com/hotel/{국가코드}/{숙소-슬러그}.ko.html` |
| CMS 판매가 | 프로필의 채널 매니저 주소 · 부킹용 상품그룹 |

채널 매니저를 안 쓰는 숙소는 판매가를 익스트라넷 요금 캘린더에서 직접 읽는다.

## 객실 이름 매핑 (CMS ≠ 부킹)

CMS의 객실명과 부킹 소비자 페이지의 객실명은 다르다. 프로필의 매핑표를 쓴다.
매핑표가 없거나 의심스러우면 **이름으로 맞추지 말고 금액으로 역산해 확인한다**:
`소비자 페이지 「기존 요금」 ÷ (요금제 배수 × 인원 계수 × 타겟 요금 배수) = 판매가`.

## 화면 조작 절차

### 세션 관리 (제일 많이 깨지는 부분)
- 익스트라넷 안에서는 **`ses=` 가 붙은 상단 네비게이션으로 이동**한다.
- **`ses=` 없는 링크는 메뉴·인박스 링크라도 로그아웃될 수 있다.** 클릭 전에 href를 확인하고, 없으면 누르지 말고 `ses=` 가 있는 상단 메뉴로 간다.
  ```js
  [...document.querySelectorAll('a')].map(x=>({t:x.innerText.trim(),ses:/[?&]ses=/.test(x.href)}))
  ```
- **주소창 직접 입력 금지 · `location.reload()` 금지** — 로그아웃된다.
- 소비자 페이지 확인은 **반드시 새 탭**에서.
- 드롭다운이 「시스템에 오류가 발생했습니다」를 뱉으면 한 번 더 클릭하면 열린다.
- 상단 메뉴 링크는 **실제 마우스로 메뉴를 연 뒤에** 생긴다. 스크립트 클릭으로는 열리지 않고 찾기 도구에도 안 잡힌다. 일부 메뉴는 「로딩 중」이 끝날 때까지 기다린다.
- 예약 상세는 새 탭으로 열린다. 다 읽으면 닫는다.
- 예약 목록·명세서의 **행 머리글(`th`)에 투숙객 이름이 있다.** `innerText` 통째 읽기, 페이지 글자 추출, `th` 전체 수집을 쓰지 말고 `thead th` 로 칸 위치를 찾은 뒤 금액 칸만 읽는다.

### 프로모션 할인율
```
프로모션 ∨ → 적용 중인 프로모션 확인하기 → 해당 행 「∨」 → 「수정」
 → #usp-discount-action 에 값 입력 (네이티브 setter)
 → 「검토」 실제 클릭 → 스크린샷 → 모달 없으면 한 번 더 → 스크린샷
 → 모달에서 할인율·대상 고객층·이름 확인 → 「적용」
```
```js
const setter=Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype,'value').set;
el.focus(); setter.call(el,'22');        // '22' 자리에 넣을 할인율
el.dispatchEvent(new Event('input',{bubbles:true}));
el.dispatchEvent(new Event('change',{bubbles:true})); el.blur();
```
- 「검토」는 **JS click이 안 먹는다.** 실제 마우스 클릭이어야 한다.
- **두 번 누르면 열린 모달이 닫힐 수 있다.** 반드시 스크린샷으로 확인하며 진행.
- 모달이 안 뜨면 값이 살아있는지 먼저 확인하고 다시 클릭.

### 요금제 배수 (주간·월간·환불불가)
```
요금 및 예약 가능 여부 ∨ → 요금제 → 해당 행 「∨」 → 「수정」
 → 「요금 차이」의 「수정」 → 숫자 → 「저장」 → 하단 「변경사항 적용」
```
- 펼친 패널의 파란 「수정」 **바로 옆이 빨간 「삭제」**다. 좌표를 정확히.
- 「저장」만 누르면 반영 안 된다. **「변경사항 적용」까지.** 초록 배너로 확인.
- **주간과 월간은 별개 요금제다. 각각 고친다.**

## 자주 밟는 함정

| 함정 | 대응 |
|---|---|
| 「Domestic」을 내국인으로 읽음 | 접속 위치다 |
| 베이직과 조기예약을 곱함 | 같은 카테고리 → 하나만 |
| 요금제 배수를 프로모션에서 찾음 | 「요금제」 화면에 따로 있다 |
| 주간만 고치고 월간 빼먹음 | 별개 요금제 |
| 기준 인원보다 적게 조회해 「안 맞는다」 판정 | 기준 인원으로 조회 |
| WEEK/FRI/SAT를 요일로 읽음 | 프로필의 요금세트 규칙 기준 |
| 다른 채널과 입금가 그대로 비교 | 부가세 포함/제외 기준이 채널마다 다르다 |
| 캠페인이 곱해진다고 계산 | Genius 미참여면 대체한다. 집중형 특가는 어떤 할인과도 중복 불가 |
| 막바지를 당일 1박 할인으로 계산 | 예약 전체 박수에 걸린다. 최심 칸에 포함 |
| 검색 카드 값을 우리 요금으로 읽음 | 상세 페이지 직판 줄끼리 비교 |
| 「검토」 두 번 눌러 모달 닫힘 | 스크린샷 확인하며 진행 |
| 주소창 이동 / 새로고침 / `ses=` 없는 링크 클릭 | `ses=` 가 붙은 상단 메뉴로 이동 |
| 「저장」만 누르고 끝냄 | 「변경사항 적용」까지 |
| 소비자 페이지 캐시를 실패로 오판 | 새로고침 후 재확인 |
| 다른 숙소·과거 문서의 계수를 그대로 씀 | 프로필과 최근 실예약으로 다시 확인 |
| 예약 1건으로 입금 계수 확정 | 숙박일별로 묶어 본다. 날짜마다 수수료가 다를 수 있다 |
| 대금 지급액을 실입금으로 읽음 | 총액 지급이면 수수료는 월 청구서로 따로 나간다 |
| 노출 향상 도구에서 「새 수수료율 적용하기」를 누름 | 조회할 때 누르지 않는다. 수수료가 올라간다 |
