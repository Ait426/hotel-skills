# 숙소 점검 — 영역별 절차 · 합격 기준

"점검해줘", "현황 봐줘", "뭐가 부족해"에 쓴다. 요금 계산(`pricing.md`)과 별개로, 숙소 페이지·프로그램·정책·노출을 훑는다.
결과는 `property.json` 의 `audit[]` 에 영역마다 한 줄로 남기고 콘솔 「점검 결과」 카드로 낸다.

**조회만 한다.** 이 문서의 화면에는 참여·취소·적용·삭제 버튼이 가까이 있다. 누르지 않는다.
기준값(점수 하한, 심사 일정, 참여 요건)은 숙소·시기마다 다르다. **화면에 적힌 값을 그대로 옮기고, 이 문서의 예시 숫자를 쓰지 않는다.**

## 0. 이동과 읽기

| 영역 | 경로 (`/hotel/hoteladmin/extranet_ng/manage/…`) | 메뉴 |
|---|---|---|
| 숙소 상태·조치 필요 | `home.html` | 홈 |
| 숙소 페이지 점수 | `content_score.html` | 숙소 → 숙소 페이지 보기 |
| 사진 | `photos.html` | 숙소 → 사진 |
| 이용후기 | `reviews.html` (`&tab=category` 항목별) | 고객 이용 후기 |
| 프로그램 자격 | `performance_dashboard.html` | 분석 도구 → 성과 대시보드 |
| Genius | `genius.html` | 성과 향상 |
| 추천 숙소 | `preferred_program.html` | 성과 향상 |
| 노출 향상 도구 | `co_add.html` | 성과 향상 |
| 스마트 플렉시블 예약 | `risk_free.html` | 성과 향상 |
| 기회 요인 센터 | `opportunities.html` | 성과 향상 |
| 요금제 | `rate_plans.html` | 요금 및 예약 가능 여부 |
| 취소·선결제 정책 | `policies.html` | 숙소 → 예약 정책 |
| 객실 구성 | `rooms.html` | 숙소 → 객실 상세 정보 |
| 검색 순위 요인 | `showrank.html` | 홈 → 검색 및 예약 성과 |

- 이동은 `snippets.js` 의 `__go(경로)` 로 한다. 현재 주소의 `ses=` 를 붙인 링크를 눌러 이동하므로 세션이 유지된다. 주소창 직접 입력은 하지 않는다.
- 메뉴 링크는 실제 마우스로 메뉴를 연 뒤에만 생긴다. 경로를 모르면 메뉴를 열고 `__sesLinks()` 로 찾는다.
- 읽기는 `__mainText()` 로 한다. 상단 메뉴를 빼고 본문만, 예약번호를 가린 채 돌려준다.
- **이용후기·예약·메시지 화면은 본문 통째 읽기 금지.** 목록에 투숙객 이름과 예약번호가 섞여 있다. 후기는 `__reviewSummary()` 로 요약 부분만 읽는다.

## 1. 숙소 상태 — `home`

상태 배지(예: 공개/예약 가능)와 오른쪽 「조치 필요」 목록을 적는다. 상태가 예약 가능이 아니면 다른 점검보다 `suspension.md` 가 먼저다.

합격: 예약 가능 상태, 조치 필요 0건.

## 2. 숙소 페이지 점수 — `content_score`

점수(%)와 **완료되지 않은 항목**만 적는다. 「완료!」가 붙은 항목은 옮기지 않는다. 같은 화면의 다른 숙소 점수는 비교용으로만 쓰고 결과물에 숙소명을 남기지 않는다.

합격: 미완료 항목 0. 점수가 높아도 미완료 항목은 조치 목록에 넣는다.

## 3. 사진 — `photos`

상단 요약 네 칸을 읽는다: 모든 사진 · 저화질 사진 · 사진이 없는 숙박옵션 · 태그가 없는 사진. 객실별 장수도 적는다.

합격: 저화질 0, 사진 없는 객실 0, 태그 없는 사진 0. 숙소 페이지 점수의 사진 항목(조식·외관 등)과 같이 본다.

## 4. 이용후기 — `reviews`

`__reviewSummary()` 로 총점, 후기 수, 항목별 점수를 읽는다. 항목별 점수는 `&tab=category` 화면에 다 나온다. **최저 항목**을 표시한다.
미답변 후기는 목록의 「답변하기」 버튼 수를 세되, 첫 화면 기준이면 그렇게 적는다.

합격: 숙소가 정한 목표 이상. **추천 숙소·Genius 요건 점수와의 여유**를 같이 적는다 — 이 값이 프로그램 자격을 가른다.

## 5. 프로그램 — `performance_dashboard` · 각 프로그램 화면

프로그램마다 **상태 · 요건(화면 문구 그대로) · 현재 값 · 여유 · 다음 심사일**을 적는다.

| 프로그램 | 볼 것 |
|---|---|
| 추천 숙소 | 참여 상태, 성과 점수와 하한, 후기 평점과 하한, 외부 요금 경쟁력, 다음 자격 심사 기간, 제외 시 재참여 제한 |
| Genius | 참여 가능 여부, 못 하는 이유(후기 점수·후기 수 등), 참여 시 최소 할인 조건 |
| 노출 향상 도구 | 현재 수수료, 날짜별로 올린 수수료가 있는지. 「새 수수료율 적용하기」는 누르지 않는다 |
| 스마트 플렉시블 예약 | 참여 여부. **참여 중이면 일부 요금제의 취소 정책이 무료 취소로 바뀌어 팔린다**(6장) |
| 장기 숙박·객실 유형 차별화 | 참여 여부만 |

- **요건에 딱 걸린 값은 위험으로 판정한다.** 예: 하한이 7.0인데 현재 7.0이면 후기 한 건으로 탈락할 수 있다. 심사일 전에 조치할 수 있게 날짜를 같이 쓴다.
- 프로그램 수수료나 비용이 입금 계수를 바꾸는지는 예약 명세서로 확인한다(`pricing.md`). 화면 설명만으로 수수료율을 추정하지 않는다.
- 외부 요금 경쟁력 표에 요금 차이 사례가 있으면 그대로 옮긴다.

## 6. 요금제와 취소 정책 — `rate_plans` · `policies`

요금제마다 명칭 · ID · 취소 정책 · 요금 성격(기준 요금제 대비 몇 % 등) · 취소율 · 매출을 적는다. 정책 화면에서는 정책별 숙박일 수 · 매출 · 취소율을 적는다.

**이름과 실제 판매 정책이 맞는지 소비자 페이지에서 확인한다.** 요금제 이름이 환불불가여도 목록의 취소 정책이 유연함이거나,
스마트 플렉시블 예약이 정책을 올려서 손님에게 「무료 취소 가능」으로 보일 수 있다. 그러면 환불불가 할인만 주고 취소 위험은 그대로 진다.
`__rates()` 의 `refund`(환불 불가 문구)와 행 문구의 「무료 취소」를 함께 본다.

합격: 할인 요금제는 소비자 페이지에서도 그 정책대로 보일 것, 취소율이 정책 성격과 맞을 것(환불불가인데 취소율이 높으면 정책이 다르게 걸려 있다는 신호).

## 7. 객실 구성 — `rooms`

객실명 · 객실 ID · 최대 인원 · 객실 수를 적는다. 판매가 계산의 객실 매핑(`portal-map.md`)과 기준 인원 확인에 쓴다.

합격: 채널 매니저의 객실과 하나씩 대응할 것, 객실 수가 실제와 맞을 것.

## 8. 검색 순위 요인 — `showrank`

화면이 보여 주는 요인(일일 평균 요금, 숙소 페이지 점수, 후기 평점, 전환율, 참여 프로그램 등)과 값을 적는다. 기간(예: 지난 90일)도 같이 적는다.
순위를 직접 바꾸는 값이 아니라 **비교용 지표**로 쓴다.

## 9. 기회 요인 센터 — `opportunities`

제안 제목과 한 줄 내용을 적는다. 숙소에 뭐가 비어 있는지 알려 주는 힌트다 — **전부 켜라는 뜻이 아니다.**
할인 제안은 `payout.py check` 로 입금가와 하한을 먼저 계산한다. 재고가 열려 있지 않은 기간 제안은 판매 기간 점검 항목으로 옮긴다.

## 기록 형식 — `audit[]`

```json
{ "area": "프로그램", "item": "추천 숙소 후기 평점", "value": "7.0 (하한 7.0)", "status": "bad",
  "rule": "후기 평점 7.0 이상, 다음 심사 1/5~1/15", "action": "심사 전 후기 관리", "source": "추천 숙소 프로그램 화면" }
```

`status`: `ok` 합격 · `warn` 주의 · `bad` 위험 · `unknown` 못 읽음. 못 읽은 영역도 `unknown` 으로 남기고 `open[]` 에 확인 방법을 적는다.
위 값은 형식 예시다.

## 아고다 스킬과 같은 산출물 — 기록 칸

점검이 끝나면 `audit[]` 말고도 아래 칸을 채운다. 콘솔이 「현재 설정 · 발견 사항 · 프로그램 · 콘텐츠 · 요금제 · 노출가 실측」 카드로 낸다. 칸 이름은 아고다 스킬과 같다.

| 칸 | 어디서 읽나 | 무엇을 적나 |
|---|---|---|
| `findings` | 아래 영역에서 나온 결론 | 심각도(high·med·info) · 근거 · 정정 |
| `programs` | Genius · 추천 숙소 · 노출 향상 도구 · 스마트 플렉시블 화면 | 설정 가능 범위(예: 노출 향상 도구의 수수료 선택지)와 현재 설정을 나눠 적는다 |
| `content.photos` | 사진 화면 요약 | 전체 장수, 저화질, 태그 없는 사진 |
| `content.reviews` | 이용후기 항목별 탭 (`__reviewSummary`) | 총점, 건수, 항목별 점수, 미답변 건수 |
| `content.mapping` | 요금제 화면의 채널 매니저 표시 · 객실 상세 정보 | 채널 매니저와 연결된 객실 수 / 전체 객실 수 |
| `ratePlans` | 요금제 화면 | 요금제명 · 기준 요금제(파생 여부) · 취소 정책 · 상태. 예약 수는 예약 목록 필터로 센다 |
| `measurements` | 소비자 페이지 「기존 요금」「표시 요금」 | 날짜 3개 이상. 입력값은 그날 판매가 × 요금제 배수 |

- `findings[]` 는 결론이다. `{"title", "severity", "detail", "evidence", "revised"}`. **실측은 `evidence`, 판단은 `detail`** 에 나눠 적는다. 판정이 뒤집히면 `revised` 에 이전 판정과 정정 사유를 남긴다.
- `programs[]` 는 `{"name", "status", "range", "setting", "note", "verified"}`. 화면에서 못 읽은 범위는 `null` 이다. 일반 구조를 그 숙소 값처럼 적지 마라.
- `content` 는 `photos{total, lowRes, untagged, note}` · `reviews{score, count, unanswered, detail{}, compare{}, note}` · `mapping{mapped, total, unmapped, note}`. 숫자 칸에 글자를 넣지 않는다.
- `ratePlans[]` 는 `{"name", "id", "rooms", "base", "policy", "sold", "status"}`. 가격표(요금제 배수·요금)와 다른 것이다. `sold` 가 0이면 `--check` 가 알린다.
- `measurements[]` 는 `{"label", "condition", "input", "shown", "expected", "tolerance"}`. **날짜 3개 이상**을 재서 화면값 ÷ 입력값 비율이 0.001 안에서 맞으면 공식이 선형으로 확인된 것이다. 조회 조건(국가·기기·박수·인원·로그인)을 `condition` 에 적는다.
- `promoGroups[]` 는 **중복 규칙을 계산기에 넣는 칸**이다(아고다 `promotions.groups` 와 같은 역할). `{"name", "mode", "items": [{"name", "pct", "on", "tag"}]}`. `mode` 는 `locked`(항상 적용) · `single`(그룹에서 하나만, 라디오) · `multi`(누적, 체크박스). 켤 수 없는 조합을 계산기가 애초에 못 만들게 이 스킬의 `pricing.md` 중복 규칙대로 그룹을 짠다. 하나만 붙는 그룹에 실제로 2개가 켜져 있으면 `on` 은 하나에만 주고 나머지는 `tag` 에 「적용 중」을 적는다.
- `commissionParts[]` 는 **수수료 조합 비교 칸**이다(아고다 `commission.parts` 와 같은 역할). `{"name", "kind", "pct", "options"}`. `kind` 는 `base`(손님 결제액에서 차감) · `accel`(세전 금액에서 차감). `options` 에 화면의 선택지를 넣으면 드롭다운으로 바꿔 가며 입금가를 비교한다. **pct 를 모르면 null 대신 항목을 뺀다.** 광고비처럼 입금가 공식 밖의 비용은 넣지 않는다.
- `summary[]` 는 맨 위 요약 칸 `{"label", "value", "note"}` 이다. 수수료·계수처럼 그 숙소의 핵심 숫자를 넣는다. 적용 중 프로모션 수·발견 사항·점검 건수·하한은 자동으로 붙는다.
