# 손님 유형 → OTA 설정

**이 배포본에는 특정 숙소의 값이 없다.** 객실 수, 채널 이름, OTA 할인·수수료·하한은 전부 프로필과 매핑에서 온다.

목적은 한정된 객실로 **매출과 점유율을 같이 올리는 것**이다. 판단은 RevPAR(판매 가능 객실 1실당 매출)로 한다.
- 비는 날은 그 날에 실제로 예약하는 손님 유형에 맞춰 할인을 연다.
- 꽉 찬 날은 할인을 줄인다.
- 할인 추천은 반드시 입금가 하한 검산을 거친다.

## 흐름

1. **입력 확인**: PMS 예약 내보내기 1개가 필수다. 아래는 있으면 더 쓴다.
   - 트립 주문(국적·요금제)
   - 부킹 예약(인원)
   - 국내 OTA 예약내역(대실·회원등급·쿠폰)
2. **프로필**: `assets/profile.example.json` 을 복사해 채운다.
   - `rooms`: 객실 타입별 실수
   - `ota`: 채널별 property.json 경로
   - 모르는 값은 비워 둔다. **지어내지 않는다.**
3. **매핑**: `scripts/mapping-template.json` 을 복사한다.
   - 내 파일의 **열 이름만** 보고 맞춘다. 값이 든 행은 대화에 옮기지 않는다.
   - YFlux 예약 통합 검색 내보내기는 pms 열 이름이 양식과 같다.
4. **실행**: 아래 「실행」 절의 명령을 돌린다.
   - 채널 파일 건수가 적으면 `--extra-start` 로 채널 파일만 더 긴 기간(예: 최근 12개월)을 본다.
5. **결과 대조**: 채널별 건수·매출·취소율을 PMS 보고서나 staytools-sales-analysis 결과와 먼저 맞춘다. 맞지 않으면 추천을 보여 주지 않는다.
6. **보고**: `report.html` 의 「채널별 할 일」을 짧게 요약한다.
   - 할인 추천은 각 OTA 콘솔(agoda-audit, booking-rate-ops, expedia-payout, trip-payout)에서 값을 넣어 다시 확인하라고 안내한다.
   - 적용은 사용자가 직접 한다.

## 실행

```
python scripts/segment_report.py --pms 예약.xlsx --mapping mapping.json --profile profile.json --out-dir 결과 --month YYYY-MM --extra 트립닷컴=trip.csv --extra 부킹닷컴=booking.csv
```

## OTA property.json

각 OTA 스킬이 만든 property.json 을 그대로 쓴다(`promoGroups`, `commissionParts`, `rooms[].rates`, `property.floor`/`coef.floor`).
아고다는 `promotions.groups`, `commission.parts`, `weekly[].cms` 를 읽는다.
property.json 이 없거나 비어 있는 채널은 「확인 필요」로 남긴다. 그 채널의 할인율을 추측해서 채우지 않는다.

## 손님 유형 축

- **PMS**: 채널, 예약 시점(당일/1~3/4~7/8~30/31일+), 박수(대실/1/2/3~6/7+), 체크인 요일, 객실 타입, 인원(1/2/3인+), 요금 유형, 취소율
- **교차**: 채널×예약 시점, 채널×박수, 채널×요일. 기간에 여러 달이 있으면 월별 추이도 낸다.
- **채널 파일**: 국적, 요금제, 식사, 프로모션, 인원, 회원등급, 쿠폰, 국적×요금제
- **점유율**: 날짜×객실 타입별 판매 객실박 ÷ 실수. 대실은 뺀다.

규칙과 검산 공식은 `references/rules.md` 에 있다.

## 해석 주의

- PMS 체크인이 실제 입실 시각인 PMS(자정 넘어 입실)는 요일·리드타임이 하루씩 밀릴 수 있다. staytools-sales-analysis 의 예정일 보정 설명을 참고한다.
- 국적은 채널 파일(트립 등)에만 있다. 국적 열이 이름에서 추정한 값이면 "추정"이라고 밝힌다.
- 표본이 `min_n` 미만이면 "표본 적음"으로 표시하고 결론을 내지 않는다.
- 검산은 대표 판매가 하나로 한다. 요일·객실별 판매가가 다르면 OTA 콘솔의 요일별 일괄 표로 다시 본다.
- 추천은 과거 예약 분포에서 나온 제안이다. 효과는 적용 뒤 같은 기간을 다시 돌려 비교한다.

## 개인정보

- 예약번호·확정번호·이름·연락처·이메일 열은 매핑하지 않는다. 매핑하면 스크립트가 멈춘다.
- 매핑하지 않은 열은 읽자마자 버린다.
- 결과 파일에는 예약번호와 이름이 없다. 그래도 실제 숙소 결과는 외부에 올리지 않는다.
- 로그인과 화면 조작은 하지 않는다. 사용자가 내려받은 파일만 읽는다.
